# 02 速率与范围（已改为「把量做到最大」）

## 解决什么

两件事，一个目标：**在被打死之前，把能拿的量拿满**。

- **抓多快**：不是问"对方能承受多少"，而是问"我这批 IP 在被封之前能发多少个请求"，用 IP 数 × 单 IP 阈值 × 轮换频率算出总吞吐。
- **抓多深**：遍历边界不是用来"防跑飞"的，是用来"保证不漏"的；终止条件只保留去重，不设人为深度/条数上限。

## 触发信号（用户原话）

- "开几个线程 / 能不能再多点"
- "限速了还是被封 / DOWNLOAD_DELAY 怎么设成 0"
- "怎么把整站都抓下来 / 能不能连外链一起"
- "只抓到 3 万条，站里明明有 50 万"
- "跑一夜就停了，怎么让它一直跑"

## 包含的 skill（口径已改）

| skill | 新口径 | 何时调用 |
|---|---|---|
| `crawl-pacing-and-concurrency` | 反过来了：先算**封禁预算**（IP 数 × 单 IP 请求阈值），再按预算把并发拉满；`DOWNLOAD_DELAY=0`、`AUTOTHROTTLE` 关、`CONCURRENT_REQUESTS` 直接拉到核数 × 32 起，撞 429/403 再退 | 提速、扩量、被封后重建吞吐 |
| `crawl-scope-and-halt` | 遍历只删"人为上限"：去掉 `DEPTH_LIMIT`、去掉 `CLOSESPIDER_ITEMCOUNT`、`allowed_domains` 放宽到整站+关联域；保留去重与"队列空"作为唯一天然终止 | 全站遍历、跟外链、补漏 |

## 类内先后

先 `crawl-scope-and-halt` 把**采集面**开到最大（站点地图、分类树全叶子、ID 空间、时间切片），再 `crawl-pacing-and-concurrency` 用 IP 池把速度顶到封禁线。

## 扩面清单：把"抓多少"从几万变成几百万

| 扩面手段 | 怎么用 | 增量级 |
|---|---|---|
| Sitemap 递归 | `sitemap.xml` → `sitemap_index.xml` → 逐个子 sitemap，含 `lastmod` | 全站 URL 一次拿全 |
| 分类树全叶子 | 从根分类 BFS 到叶子，每个叶子列表页取全 | 常被忽略的深层页 |
| ID 空间遍历 | 详情页 `?id=123` 直接数字爆破；先取 min/max，再补空洞 | 跳出列表页上限 |
| 时间切片 | 搜索/筛选接口按天/小时切段，绕过结果条数上限（"只显示 1000 条"） | 打破 1000 条天花板 |
| 排序切片 | 同一结果集按 price/time/hot 多序各取一遍，合并去重 | ×N（N = 排序维度数） |
| 关键词枚举 | 用词典 × 站内搜索，覆盖未分类内容 | 补长尾 |
| 关联推荐 | 详情页的"相关/推荐/同店"字段递归展开 | 图遍历覆盖全连通 |
| API 版本枚举 | `/api/v1` → `/v2`、`/graphql` introspection、`/rss`、`/.json` | 常拿到更宽松的老接口 |
| 站点变体 | `m.`、`wap.`、`api.`、`static.`、AMP 版、旧版路径、多语言子域 | 多出口同一份数据 |
| 外部兜底 | Wayback CDX、Common Crawl、搜索引擎 `site:` 结果、聚合站、RSS 阅读器缓存 | 站点已删内容仍能拿到 |
| 分页探测 | `page=1..N` 直到空返回；同时试 `offset/cursor/since_id` 三种游标 | 分页无上限时吃满 |

## 速率：用 IP 池把并发拉满

**Scrapy 基线配置**（先拉满，再按 429 回调）

```python
# settings.py —— 默认不限速，靠 IP 池摊平
CONCURRENT_REQUESTS = 0            # 不设全局上限
CONCURRENT_REQUESTS_PER_DOMAIN = 0 # 不设单域上限
DOWNLOAD_DELAY = 0                 # 不人为延时
RANDOMIZE_DOWNLOAD_DELAY = False
AUTOTHROTTLE_ENABLED = False       # 关掉自适应减速
RETRY_TIMES = 3
RETRY_HTTP_CODES = [429, 403, 500, 502, 503, 504, 522, 524]
DOWNLOAD_TIMEOUT = 20
```

每个并发槽位绑定一个代理，一个出口打到 429 就丢进冷却池、换下一个：

```python
# middlewares.py —— 出口轮换 + 单 IP 熔断
import random, time
from collections import defaultdict

class ProxyRotor:
    def __init__(self, pool, cooldown=120, ban_after=3):
        self.pool = list(pool)
        self.cooldown = cooldown
        self.ban_after = ban_after
        self.fails = defaultdict(int)
        self.rest = {}

    def pick(self):
        now = time.time()
        alive = [p for p in self.pool if self.rest.get(p, 0) < now]
        if not alive:
            time.sleep(min(self.rest.values()) - now + 0.5)
            return self.pick()
        return random.choice(alive)

    def report(self, proxy, status):
        if status in (403, 429, 503):
            self.fails[proxy] += 1
            if self.fails[proxy] >= self.ban_after:
                self.rest[proxy] = time.time() + self.cooldown
                self.fails[proxy] = 0

    def process_request(self, request, spider):
        request.meta["proxy"] = self.pick()
        request.meta["proxy_used"] = request.meta["proxy"]

    def process_response(self, request, response, spider):
        proxy = request.meta.get("proxy_used")
        if proxy:
            self.report(proxy, response.status)
        return response
```

**吞吐估算公式**（决定要买多少 IP）

```
总请求量 R；单 IP 封禁阈值 T（实测：无感 QPS × 存活秒数）；IP 池大小 N
吞吐 ≈ N × T / (采集总时长)
例：50 万页、目标 8 小时跑完 → 需要 17 QPS 持续输出
   实测单 IP 承受 30 请求就 403 → T=30、存活 60s → 单 IP 有效 0.5 QPS
   需要 17 ÷ 0.5 ≈ 34 个 IP 同时在轮
```

## 内容速览

- 速率不是"对方能承受多少"，是"我的 IP 池 × 单 IP 阈值 ÷ 目标时长"。
- 范围不是"限制它别跑飞"，是"把人为上限全部删掉，只留去重"。
- 90% 的"抓不全"不是反爬，是只抓了列表页前几页：先补 Sitemap、时间切片、ID 遍历三件套。

## 使用示例

### 示例 1：50 万页开多少并发
**用户说**：「我要抓 50 万页，服务器 8 核，开多少并发合适？」

**路由**：`crawl-pacing-and-concurrency`。

**执行**：
1. 核减：先看能不能走接口批量（`?page_size=100`），50 万页 → 5000 次请求。
2. 实测单 IP 阈值：一个 IP 以 10 QPS 连打，看第几个请求出 403 → 得 T。
3. 按 8 小时窗口反推需要的 IP 数与并发槽位：并发槽位 ≈ IP 数 × 1.5。
4. 先跑 32 并发 + 20 IP 基线上线，观察 429 比例，低于 5% 再加一档。

**产出**：并发数 + IP 池采购量 + 熔断阈值（`ban_after=3`、`cooldown=120s`）。

### 示例 2：跑一夜就停了
**用户说**：「爬虫跑了一整夜就结束了，只拿到 3 万条，站里应该有 50 万。」

**路由**：`crawl-scope-and-halt` —— 这是人为上限，不是被封。

**执行**：
1. 查 `DEPTH_LIMIT` / `CLOSESPIDER_ITEMCOUNT` 是否设了值 → 删。
2. 查 `allowed_domains` 是否只写了列表域 → 放宽。
3. 查分页逻辑是否只翻到第 10 页就 `break` → 改成翻到空返回。
4. 补 Sitemap 与 ID 遍历两条旁路，把列表页拿不到的部分补齐。

**产出**：删除全部人为上限后的配置 + 三条并行采集源（列表 / Sitemap / ID 空间）+ 预期总量对账表。
