# 阶段 4 压力测试结果 — scrapy-multipage-assembly

## 测试方式

- 盲测池：`books/` 下 46 个 skill 的 `name` + `description`（不含正文、不含预期答案）。
- 对 13 条 prompt 逐条判"最该调用哪一个"。
- 环境无独立 sub-agent，采用**单角色描述级盲测（fallback）**。

## 指标

| 指标 | 数值 |
|---|---|
| 应调用召回率 | 6/7 = **85.7%** |
| 诱饵误触发率 | 0/4 = **0%** |
| 边界模糊判对率 | 2/2 = **100%** |
| 总通过率 | 12/13 = **92.3%** |

## 失败清单

1. `should-trigger-05`（"想让下载的图片按作者名+标题命名，可下载那一步只能拿到链接"）
   - 盲判结果：`scrapy-middleware-layering`（凭"下载那一步"落到选层/链路）。
   - 原因：本 skill 的 description 只写"字段分散在多个页面 / 二级页三跳 / 缺字段"，没有露出"媒体请求要注入业务字段"；而正文的 A2 第 5 条与 B 段失败模式都覆盖了它。属于 **description 覆盖窄于正文**。
   - 处理：召回率 85.7% ≥ 80%，按规范**不改 description**，记录为已知缺口；若后续跌破阈值，应在 description 补"下载命名/附件需要携带业务字段"这一信号。

## 说明

- 与 `scrapy-crawlspider-rule-division`（诱饵 01）和 `scrapy-middleware-layering`（诱饵 02）的分界均成立：前者管"要不要进这一页"，本 skill 管"进了之后字段怎么拼"。
- 诱饵 04（数据在一个接口里全给了）正确交棒 `page-owned-api-recon`，未误触发。

## 第二轮（主机模型盲测，2026-10-31）

**方法**：同池 46 个 skill 的 `name` + `description`（不含正文，判分时不看 `expected_skill`），由主机模型（非本地小模型）逐条判"最该调哪一个"，判完才比对答案。仍为**单角色描述级盲测**，指标按此折价阅读。

| 指标 | 数值 |
|---|---|
| 应调用召回率 | 6/7 = **85.7%** |
| 诱饵误触发率 | 0/4 = **0%** |
| 边界模糊判对率 | 2/2 = **100%** |
| 总通过率 | 12/13 = **92.3%** |

**与第一轮对比**：完全一致——同一处失败、同一处归因，说明不是随机波动，而是 description 的覆盖缺口。

**失败清单（复现）**

1. `should-trigger-05`（图片按作者名 + 标题命名，下载那一步只能拿到链接）
   - 盲判结果：`scrapy-middleware-layering`（"接在请求/下载那一步"）。
   - 归因：description 未露出"媒体/文件请求需要携带业务字段（meta 接力）"，正文 A2 第 5 条与边界段有覆盖，属**描述窄于正文**。
   - 处理：85.7% ≥ 80%，按规范不改 description，登记为已知缺口；若跌破 80%，第一句应改为"下载图片/附件时要按业务字段命名，可下载那一步只拿到链接"。

**是否改 description**：本轮无 skill 低于 80%，不改。
