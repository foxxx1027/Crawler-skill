# 01 Scrapy 框架

## 解决什么

Scrapy 项目里八个最高频的"明明写了却不生效/不推进/缺东西"：接新站、登录、Cookie 过期、中间件顺序、规则不跟进、多页拼装、配置被覆盖、上生产。

## 触发信号（用户原话）

- "新站接入，不知道数据在不在 HTML 里"
- "模拟登录提交成功却还是未登录"
- "跑久了结果全空 / 302 跳登录页"
- "中间件没生效 / 顺序不对 / 请求消失了"
- "CrawlSpider 只抓到起始页 / rules 不跟进"
- "成功率很高但入库缺字段"
- "settings.py 改了没反应"
- "要上生产 / 断点续跑 / 部署形态怎么选"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `scrapy-new-site-onboarding` | 先用 Scrapy Shell 验"数据在不在初始 HTML"，再起骨架；含"页面与浏览器不一致"分诊 | Scrapy实战 | 接手陌生站点要每天同步 |
| `scrapy-login-route-choice` | 三步定位（真实接口、真实字段名、成功判据）→ 按"复现加密成本 × 账号数"在 FormRequest 与 Cookie 两条路线间选 | Scrapy实战 | 模拟登录、登录成功仍显示未登录 |
| `scrapy-cookie-pool-selfheal` | Cookie 当可轮换资源：收集 → 注入 → 检测 → 替换闭环，UA 与 Cookie 来自同一身份包 | Scrapy实战 | 登录态会过期、多账号轮换、长跑全空 |
| `scrapy-middleware-layering` | 判该写 Downloader 中间件、Spider 中间件还是 Pipeline；按 order 与"请求为什么消失"排查 | Scrapy实战 | 中间件不生效/顺序错/403 404 进不了回调 |
| `scrapy-crawlspider-rule-division` | 按页面角色拆规则（列表页/详情页各自的 allow/deny 与 callback），核对 parse 是否被占用、入口是否接回 | Scrapy实战 | 只抓到第一页、rules 不跟进 |
| `scrapy-multipage-assembly` | 用 meta 携带半成品逐跳补字段，按 Failure 类型分派补救，末跳前断言字段齐备 | Scrapy实战 | 一个 Item 的字段分散在多个页面 |
| `scrapy-settings-precedence-triage` | 按 `-s > custom_settings > project settings > default_settings` 找覆盖者，先确认是否在项目内 | Scrapy实战 | 配置改了不生效 |
| `scrapy-production-setup` | 按"遍历什么、抽哪类页"选 Spider 类型；覆盖默认 16 并发零延时；每条 allow 配 deny；JOBDIR 让长任务可续跑 | 用 Python 写网络爬虫 | 上生产、重启后重复抓 |

## 类内故障 → skill 对照

| 症状 | 先查 |
|---|---|
| 页面抓下来是空壳 | `scrapy-new-site-onboarding` |
| 302 跳登录 / 结果全空 | `scrapy-cookie-pool-selfheal` |
| 提交登录成功但仍是游客 | `scrapy-login-route-choice` |
| 规则不跟进 / callback 不调 | `scrapy-crawlspider-rule-division` |
| 请求凭空消失 / 403 进不了回调 | `scrapy-middleware-layering` |
| 入库记录缺字段 | `scrapy-multipage-assembly` |
| 改了配置没反应 | `scrapy-settings-precedence-triage` |
| 重启后重复抓 / 并发过高 | `scrapy-production-setup` |

## 不该在这里解决

- 只需算速率预算 —— 转 `06-工程化与运行/02-速率与范围`。
- 只需内容缓存 —— 转 `06-工程化与运行/03-缓存与复用`。
- 单请求例外 —— 转 `02-取数与请求/01-单请求复现`。

## 已知缺口

- `scrapy-new-site-onboarding` 与 `scrapy-multipage-assembly` 的 description 比正文窄（各有一条边界用例召回失败，85.7%），涉及"媒体下载命名""出口未定"。遇到这类问题时直接读正文 B 段，不要只看 description。

## 使用示例

### 示例 1：新站 parse 全空
**用户说**：「刚接一个新站，parse 里 xpath 全是空的，但浏览器打开明明有数据。」

**路由**：`scrapy-new-site-onboarding` —— 先验"数据在不在初始 HTML"，再写 parse。

**执行**：
1. `scrapy shell` 打开目标 URL，直接搜页面上的第一句话。
2. 搜不到 → 数据在接口里，转 `02-取数与请求/02-接口与表格`；**不要**在这里加 `dont_filter`、加延时、换 UA。
3. 搜得到 → 起骨架：写 parse、每条 allow 配 deny、设定终止条件。
4. 若"Scrapy 看到的内容与浏览器不一致"，按分诊表先查是否被拦（转 `03-反爬对抗与逆向/01-通道与封禁`）。

**产出**：能跑通的 spider，或一句明确结论"数据不在初始 HTML 里"。

### 示例 2：改了 settings 没反应
**用户说**：「我在 settings.py 里把并发改成 1，跑起来还是 16 并发。」

**路由**：`scrapy-settings-precedence-triage` —— 先找覆盖者，不要改代码。

**执行**：按优先级倒查：命令行 `-s` > spider 的 `custom_settings` > 项目 `settings.py` > 默认值；再确认部署环境（cron/容器）是否用了另一份配置或不在项目目录内。

**产出**：覆盖来源（例："spider 的 custom_settings 里又写了一次"）+ 修正位置。
