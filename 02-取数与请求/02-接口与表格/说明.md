# 02 接口与表格

## 解决什么

页面上的数据不在初始 HTML 里，而在站点自己发的一条 JSON 请求里。这个子类负责：**证明数据不在源码里**、找到那条通道、把请求参数删到最小、以及在无文档系统上把整套接口抄成一张可重放的表。

## 触发信号（用户原话）

- "页面是空的 / 只有 logo"
- "源码里搜不到数据，但浏览器里有"
- "滚动还在出新内容"
- "接口返回 403，是不是参数不对"
- "这个内网 OA 没有 API 文档，怎么对接"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `dynamic-page-and-min-params` | 按行为判动态页（源码搜不到 + 滚动仍出新），转 XHR 找 JSON；判动态后先删参数，删一个重放一次，仍 200 且结构不变才删 | Python项目案例 | 页面空白/条数远少于所见、想给接口瘦身 |
| `page-owned-api-recon` | 复用站点自己那条取数通道，而不是驱动浏览器 | 权威指南 2e | 渲染后页面有数据、脚本拿到空壳 |
| `api-table-replication` | 三档排序：官方出口（导出/打印/开放 API）→ 封装库/SDK → 抓包复刻；确需复刻才把每个请求抄成一行，逐条重放通过才串主循环 | Python项目案例 | 无 API 文档的网页版系统（内网 OA） |

## 类内先后

1. `dynamic-page-and-min-params` —— 判档 + 删参数，成本最低。
2. `page-owned-api-recon` —— 判档后仍想复用页面通道时用它收敛到具体那条请求。
3. `api-table-replication` —— 整套系统要复刻时，按三档先排成本，最后才逐个抄请求。

## 不该在这里解决

- 单条请求重放不通 —— 转 `02-取数与请求/01-单请求复现`。
- 参数是加密串、找不到生成处 —— 转 `03-反爬对抗与逆向/03-Web参数定位`。
- 字段还没定、表该怎么建 —— 转 `05-解析与数据/02-建模与分页`。
- 翻页条数对不上 —— 转 `05-解析与数据/02-建模与分页` 的 `pagination-acceptance`。

## 内容速览

- 判动态页的判据是**行为**（源码搜不到 + 滚动还出新），不是技术栈。
- 403 的第一嫌疑是"多带了参数"，不是"少了身份头"。
- 删参数的终止条件是"删了也不影响返回"，不是"看起来像必要参数"。
- 复刻整套系统前必须先试三档，很多系统都有导出/打印出口。

## 使用示例

### 示例 1：列表页只有 10 条，滚动能到 200
**用户说**：「源码里只搜到 10 条，滚到底能加载 200 条，怎么抓全？」

**路由**：`dynamic-page-and-min-params`。

**执行**：
1. 判档：源码搜不到 + 滚动仍出新 → 动态页，进 XHR。
2. Network → XHR，找返回列表数组的那条（如 `all_items`）。
3. 把 URL 拷进脚本，**逐个删参数、每删一个重放一次**：仍 200 且结构不变就删掉。
4. 剩下的才写成模板，标出哪个是游标、哪个是每页条数。

**产出**：一条最小 URL 模板 + 参数说明。例：`?page=2&size=50&_=1699...` 删到只剩 `page` 与 `size`，`_` 可删。

### 示例 2：内网 OA 没有文档
**用户说**：「公司 OA 没有 API 文档，我要每天同步工单列表。」

**路由**：`api-table-replication` —— 先试三档，复刻放最后。

**执行**：
1. 找官方出口：有没有导出 Excel / 打印 / 开放 API。
2. 找封装库或 SDK。
3. 都不行才抓包复刻：每个请求抄一行（描述 / 地址 / 方法 / 静态参数 / 动态参数 / 返回值），**每行单独重放通过**后才串主循环。

**产出**：一张可重放的接口表。任一行重放不通就停下修那一行，不要带着坏行串流程。
