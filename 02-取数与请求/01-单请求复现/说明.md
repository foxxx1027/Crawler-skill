# 01 单请求复现

## 解决什么

浏览器里点一次能成功，脚本里发一模一样的 URL 却失败。这个子类把"一次成功请求"完整搬进代码：方法、头、Cookie、表单字段、一次性令牌，以及写操作之后怎么确认真的写进去了。

## 触发信号（用户原话）

- "我把浏览器里的请求抄下来，返回的不一样"
- "表单提交了没报错，但页面没变"
- "登录成功但还是显示未登录"
- "隐藏字段每次都不一样 / _formkey / CSRF token"
- "响应格式不对，是不是少传了字段"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `http-request-replication` | 把一次请求抄成"描述/地址/方法/参数/返回值"一行，静态与动态参数分开标，单条重放通过才串主循环 | 权威指南 2e | 复现表单、登录、某次具体请求 |
| `form-hidden-state-and-readback` | 把一次性隐藏 token 与会话 Cookie 当作同一次 GET 的产物；字段靠遍历读取而非猜；写后必须回读断言 | 用 Python 写网络爬虫 | 登录/提交"没报错但没生效" |

## 类内先后

先用 `http-request-replication` 打通单条；若卡在隐藏字段、Cookie 罐或"提交成功但没生效"，进 `form-hidden-state-and-readback`。

## 不该在这里解决

- 要绕验证码/MFA 或未授权访问 —— 本子类不给这类配方，转 `03-反爬对抗与逆向/02-人机验证` 做成本判断。
- 官方已有 API —— 不必复刻，转 `02-接口与表格`。
- 需要多跳页面拼一个对象 —— 转 `06-工程化与运行/01-Scrapy框架` 的 `scrapy-multipage-assembly`。

## 内容速览

- 动态参数（时间戳、一次性 token、签名）必须与**同一次会话**的产物对齐，不能跨请求复用。
- 隐藏字段不要按名字猜，遍历表单读出来。
- 写操作的验收标准是**回读**，不是 HTTP 200。

## 使用示例

### 示例 1：登录返回 200 但还是游客
**用户说**：「我用 requests 提交登录表单，状态码 200，但后面请求全是未登录。」

**路由**：`form-hidden-state-and-readback` —— 这是"提交成功"与"真的登录"两件事被混为一谈的典型。

**执行**：
1. 先 GET 登录页，**遍历**所有 `input`（不要按名字猜），把隐藏字段（`_token`/`csrf`/`timestamp`）全抓出来。
2. 必须在**同一个 session** 里提交，让 Cookie 罐连续。
3. 做回读断言：带同一 session 请求一个"只有登录才能看到"的页面，检查是否出现用户名/头像。
4. 仍失败就比对：隐藏字段是否来自另一次 GET？Cookie 是否在提交时被替换？

**产出**：可复用的登录态 session + 一张字段清单（静态参数 / 动态参数分开标注）。

### 示例 2：这条请求要签名
**用户说**：「这个接口要 sign，帮我复现这条请求。」

**路由**：不走本子类 —— 不是"抄请求"，而是"算参数"，转 `03-反爬对抗与逆向/03-Web参数定位`。本子类只在签名已能算出后，用来把整条请求一比一复现。
