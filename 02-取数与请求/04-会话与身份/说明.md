# 04 会话与身份

## 解决什么

请求能发出去、参数也对，但**返回的是别人的视角或直接空数据**：没登录、登录态过期、账号权限不够、拿到的是游客视图。这一层处理"以谁的身份去取"。

## 触发信号（用户原话）

- "接口返回空 / 只有标题没有内容"
- "cookie 早上还能用，下午就失效了"
- "要登录才能看，怎么过登录墙"
- "换了账号数据就不一样，是不是权限问题"
- "这个 token 能不能复用 / 能撑多久"

## 包含的 skill

| skill | 作用 | 何时调用 |
|---|---|---|
| `login-wall-and-paywall-harvest` | 登录墙 / 付费墙 / 验证码墙后面的内容：账号池、Cookie 与 Token 复用、会话轮转、被踢后自动恢复 | 目标需要登录才出数据 |
| `auth-session-and-federation-security` | 会话生命周期、Cookie 作用域、JWT/OAuth/SAML 结构核对：判断"这条会话还能活多久、绑了什么" | 判断会话能否复用、会不会被设备/IP 绑死 |
| `access-control-and-idor` | 主体—对象—动作授权矩阵：判断同一个账号能看到哪些对象，哪些是越权可见的 | 想确认"低权限账号能不能看到全部数据" |

## 类内先后

先 `login-wall-and-paywall-harvest` 把会话拿到手 → `auth-session-and-federation-security` 判它能活多久、绑什么 → `access-control-and-idor` 判这个身份能看到多大范围。

## 不该在这里解决

- 会话拿到了但仍然 403 / 空白 —— 转 `03-反爬对抗与逆向`。
- 参数被加密、需要签名 —— 转 `08-请求层逆向与签名`。
- 想要更多入口而不是更深权限 —— 转 `07-扩量与工具链`。

## 内容速览

- 会话三件套：cookie（谁）、token（能不能动）、指纹（是不是同一台设备）。缺一件就会被降级成游客视图。
- **登录态 ≠ 数据权限**：能进后台页不代表能翻全部条目，授权矩阵要单独判。
- 会话续期比会话获取重要：抓一次用到底的写法，寿命通常只有几小时。

## 使用示例

### 示例 1：接口只返回壳数据
**用户说**：「列表接口返回 200，但 `data` 是空的，浏览器里明明有内容。」

**路由**：本子类。

**执行**：比对浏览器与你请求的 cookie 差异（重点 `_m_h5_tk`、`cookie2`、`unb`）→ 用同一浏览器导出全量 cookie（含 httpOnly）→ 回灌后重放 → 仍为空则用 `access-control-and-idor` 判是否权限不足。

**产出**：一份可用会话 + 该会话的数据可见范围结论。

### 示例 2：会话半天就死
**用户说**：「跑两小时就开始返回未登录，得手动重登。」

**路由**：`auth-session-and-federation-security`。

**执行**：读会话 cookie 的过期与作用域 → 判断是否与设备指纹/ IP 绑定 → 加定时续期与失效探测（每 N 次请求打一次探测接口）→ 失效时走自动重取而非人工重登。

**产出**：续期策略 + 失效探测器 + 自动重登的触发条件。
