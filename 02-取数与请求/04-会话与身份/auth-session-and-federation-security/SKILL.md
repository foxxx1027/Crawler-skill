# 身份认证与会话管理（工程检查清单）

## R — 原文 (Reading)

> 弱口令、默认口令、暴力破解、撞库
>
> 多因素认证、验证码、密码策略
>
> 会话固定、会话超时、注销失效
>
> Cookie 安全属性：HttpOnly、Secure、SameSite
>
> JWT、OAuth、SAML、单点登录配置缺陷
>
> — 用户，《漏洞筛查覆盖框架》第 2 类「身份认证与会话管理」，2026-10-19

## I — 方法论骨架 (Interpretation)

1. **先找齐身份入口，而不是从某个登录框开始。** 把登录、注册、找回密码、修改密码、MFA 绑定与重置、验证码发送、第三方登录、API 令牌签发、管理后台登录、SSO 回调全部列成入口清单，并标注每个入口的凭据类型（口令、短信、TOTP、证书、联邦断言）和身份来源（本地库、IdP、LDAP）。遗漏找回密码或 MFA 重置入口，是后续判断全盘偏差的主要原因。

2. **再判认证强度，区分设计、实现与配置。** 口令策略要看长度、弱口令黑名单、泄露口令比对和复用限制，而不是只看“是否要求大小写数字符号”；暴力破解要看按账号、按 IP、按设备三个维度的退避与锁定，以及撞库特征识别；默认口令属于配置问题，弱口令策略缺失属于设计问题，限速只做在前端属于实现问题。常见误判是看到有验证码就认为爆破已解决。

3. **判 MFA 与验证码是否绑定“会话 + 动作 + 目标”。** MFA 要通过独立通道完成，绑定失败次数、绑定前需重新认证、备用码一次性；验证码要绑定手机号/邮箱、业务动作、有效期和尝试次数，且服务端校验。验证码可重复使用、只在前端校验、换号即可绕过、MFA 可在未重新认证时重新绑定，都是实现缺陷；管理员不强制 MFA 则是设计缺陷。

4. **判会话生命周期，这是最容易漏的一段。** 登录成功后是否轮换会话 ID（防会话固定）；注销是否在服务端销毁会话而不只是清 Cookie；空闲超时与绝对超时是否都存在；改密、重置 MFA、禁用账号后是否撤销既有会话；并发会话是否可见可踢；“记住我”令牌是否可撤销。只抓到旧 Cookie 仍能访问，就说明注销或轮换没有真正落地。

5. **判 Cookie 的传输与作用域。** 逐项核对 HttpOnly、Secure、SameSite、Path、Domain，以及是否使用 `__Host-`/`__Secure-` 前缀；Domain 过宽会把会话暴露给兄弟子域，Path 不能当作安全边界，SameSite=None 必须配合 Secure 并评估 CSRF。会话 ID 出现在 URL、日志、Referer 中属于实现缺陷；遗漏标志往往只是框架默认值问题，但后果同样是会话被窃取。

6. **判 JWT 自身是否被当作可信凭据。** 服务端必须固定允许的算法并用密钥验签，拒绝 `none` 与算法混淆；校验 exp、nbf、iat、aud、iss；密钥要有轮换与隔离，`kid` 不能拼接成注入点；角色、租户等授权声明不能盲信令牌内容，敏感操作仍要回源校验；还要确认令牌能否在注销、改密、降权后失效。把无状态 JWT 当成长效会话、又不做撤销，是设计层的典型错误。

7. **判联合身份的整条信任链。** OAuth/OIDC 要看授权码流程、PKCE、redirect_uri 精确匹配、state 绑定、scope 最小化、code 一次性、令牌受众、公共客户端是否保管密钥、账号绑定是否可被抢占；SAML 要看断言签名而非仅响应签名、受众与 Recipient 限制、Conditions 时间窗、断言重放与 XML 签名包装；SSO 还要看 IdP/SP 元数据、注销传播和异常账号映射。只验证“能登录成功”不足以证明信任链正确。

8. **最后按“只读核查 → 授权内最小对照 → 证据定性”的顺序验证。** 先读配置、响应头、令牌结构和流程文档；再在目标范围内用自己控制的测试账号做最小对照，例如注销后重放旧会话、篡改自己令牌的 alg、把 redirect_uri 指向自己控制的回调；不要碰他人账号、真实短信通道或生产 IdP。每条结论都要绑定请求、响应、时间与账号角色，并明确它是设计缺陷、实现缺陷还是配置问题。

## A1 — 书中的应用 (Past Application)

> 本 skill 为工程清单型，没有单一书籍案例；以下为公开标准条款映射，不虚构事件细节。

### 标准映射 1: OWASP A07:2021 Identification and Authentication Failures
- **条款**: OWASP Top 10 2021 A07:2021 Identification and Authentication Failures。
- **对应检查**: 真实系统里通常表现为：允许弱口令或默认口令、登录与找回密码无频率限制、撞库无检测、MFA 可跳过或可被重新绑定覆盖、验证码可复用、会话 ID 登录后不轮换、注销后服务端会话仍有效。
- **落到本 skill**: 用 I 段第 2、3、4 模块建立“入口—强度—生命周期”核对表，产出每个入口的策略配置截图、失败响应差异和注销后重放结果，作为认证缺陷证据。

### 标准映射 2: CWE-384 Session Fixation
- **条款**: CWE-384 Session Fixation（会话固定）。
- **对应检查**: 攻击者先取得一个未认证会话 ID，诱导受害者用该 ID 完成登录；若服务端登录后不更换会话 ID，攻击者继续使用原 ID 即获得已认证会话。常见变体包括 URL 传会话 ID、子域可写 Cookie、SSO 回调后不轮换。
- **落到本 skill**: 用 I 段第 4、5 模块在授权测试账号上记录登录前后的会话标识与 Set-Cookie，确认登录、提权、改密、SSO 回调四个节点都发生轮换，并保存前后对照证据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?
- 登录、注册、找回密码、修改密码的流程要上线或做安全评审，需要一份可执行的认证检查顺序。
- 发现注销后旧设备仍在线、改密后旧会话不失效、登录前后会话 ID 不变，怀疑会话管理有问题。
- 使用 JWT 做无状态认证，想确认算法、过期、受众、角色声明和注销撤销是否可靠。
- 接入了 OAuth/OIDC、SAML 或企业 SSO，需要核对回调地址、state、PKCE、断言签名和账号绑定。
- Cookie 被安全扫描告警缺少 Secure/SameSite/HttpOnly，需要判断是配置问题还是会话泄露风险。
- 后台或高权限账号仍使用默认口令、无 MFA、验证码可绕过，需要评估认证强度与爆破面。

### 语言信号 (用户的话里出现这些就应激活)
- “注销了抓包重放还能用”
- “改完密码旧手机还能登着”
- “登录前后 session id 没变”
- “JWT 把 alg 改成 none 还能过”
- “token 里的 role 改成 admin 后端也认”
- “OAuth 回调地址能改成别的域名”
- “state 参数没看到 / PKCE 没开”
- “SAML 断言签名没校验”
- “Cookie 只有 HttpOnly，没有 Secure 和 SameSite”
- “验证码能重复用 / 换手机号就能一直发”

英文关键词：session fixation、logout does not invalidate、JWT alg confusion、OAuth redirect_uri、SAML assertion signature。

### 与相邻 skill 的区分
- 账号已经被盗、需要判断先冻结还是先改密、如何做账号分层：走 `account-compromise-layering`；本 skill 只审认证实现和会话机制，不负责止损顺序。
- 登录之后“把订单 ID 改成别人的”这类对象级越权：走 `access-control-and-idor`；本 skill 只到“你是谁、会话是否可信”，不展开主体—对象授权矩阵。
- 接口批量赋值、GraphQL 鉴权、Swagger 暴露、接口限流：走 `api-and-interface-security`；本 skill 只覆盖令牌与会话本身，接口逐端点的授权与输入输出检查交给它。
- 可疑邮件、附件、退信、邮箱分层：走 `email-trust-boundary`；本 skill 不判断邮件内容是否钓鱼，只处理登录凭据与邮件验证码通道本身。
- 前端令牌存放、CORS、CSRF、postMessage：走 `client-side-and-frontend-security`；本 skill 判断 Cookie 属性和会话语义，浏览器侧利用与前端存储策略交给它。
- 短信/邮件轰炸、验证码重复使用造成的业务滥用：走 `business-logic-and-race-security`；本 skill 只判断验证码作为认证因子是否可靠，频率与滥用面由它检查。
- 需要先明确目标范围、测试边界和披露方式：走 `pentest-engagement-and-disclosure`；本 skill 的主动验证必须以该前置结论为约束。

## E — 可执行步骤 (Execution)

1. **建认证入口与会话载体清单**
   - 动作: 列出登录、注册、找回密码、改密、MFA 绑定/重置、验证码发送、第三方登录、API 令牌、后台登录、SSO 回调等入口；为每个入口记录 URL、方法、凭据类型、身份来源、会话载体（Cookie/Header/URL）。
   - 完成标准: 形成一张“入口 × 凭据 × 会话载体 × 身份来源”表，没有未标注的登录相关端点。
   - 判停条件: 若入口数量或归属无法确认，先停在清单阶段，补资产与流量证据，不进入主动验证。

2. **标出信任边界与身份来源**
   - 动作: 标明哪些身份由本地库判定、哪些由 IdP/LDAP/社交登录断言传入；标出服务端与浏览器、服务与 IdP、服务与下游 API 之间的信任边界。
   - 完成标准: 每个入口都能回答“身份最终由谁签发、服务端是否再次验证”。
   - 判停条件: 无，继续。

3. **只读核查口令与抗爆破策略**
   - 动作: 检查口令长度与黑名单、默认口令、失败提示、锁定与退避、按账号/IP/设备的限速、撞库检测、找回密码令牌的随机性与一次性；仅在目标范围内尝试少量失败请求。
   - 完成标准: 每个策略项有“有/无/仅前端”的结论，并附配置或响应证据。
   - 判停条件: 若失败请求会锁定真实用户或触发短信费用，立即停止主动尝试，改为配置与代码核查。

4. **只读核查 MFA 与验证码绑定**
   - 动作: 确认 MFA 是否强制、绑定/重置是否需重新认证、备用码是否一次性、失败次数是否受限；确认验证码绑定手机号/邮箱、业务动作、有效期、尝试次数，且服务端校验。
   - 完成标准: 形成“MFA 环节 × 是否可绕过”和“验证码 × 绑定对象”两张表。
   - 判停条件: 无，继续。

5. **只读核查会话生命周期**
   - 动作: 记录登录、提权、改密、MFA 重置、SSO 回调前后的会话标识；检查注销、空闲超时、绝对超时、并发会话、记住我令牌撤销。
   - 完成标准: 每个生命周期节点都有“是否轮换/是否撤销”的明确结论。
   - 判停条件: 若无法获得测试账号，只输出待验证项，不把未验证项写成结论。

6. **只读核查 Cookie 与令牌传输**
   - 动作: 逐条记录 Set-Cookie 的 HttpOnly、Secure、SameSite、Path、Domain、前缀；检查会话 ID 是否出现在 URL、日志、Referer；解析 JWT 头部与声明，记录 alg、exp、aud、iss、kid 与角色声明。
   - 完成标准: 形成 Cookie 属性表和 JWT 声明表，每个异常都有原始响应行。
   - 判停条件: 无，继续。

7. **在目标范围内做最小对照实验**
   - 动作: 仅使用自己控制的测试账号，在自己控制的回调域名上验证 redirect_uri；注销后重放旧会话；篡改自己令牌的 alg/声明；比较登录前后会话 ID。不得对他人账号、真实短信通道或生产 IdP 做主动尝试。
   - 完成标准: 每组对照都有“预期—实际—差异”记录，且能排除缓存和前端假象。
   - 判停条件: 一旦实验可能影响其他用户或产生真实费用，立即停止并改用只读证据。

8. **核对联合身份配置**
   - 动作: 对 OAuth/OIDC 检查授权码流程、PKCE、redirect_uri 精确匹配、state、scope、code 一次性、令牌受众；对 SAML 检查断言签名、受众、Recipient、Conditions、重放防护；对 SSO 检查元数据、账号映射与注销传播。
   - 完成标准: 每条信任链都有“配置值—标准要求—差距”三列。
   - 判停条件: 无，继续。

9. **汇总证据、定性与修复建议**
   - 动作: 把发现分为设计缺陷、实现缺陷、配置问题；为每条给出影响、复现条件、证据位置、最小修复建议和复测方法；对无法验证的项标注“证据不足”。
   - 完成标准: 输出可直接进入修复排期的清单，且不把配置问题夸大为设计缺陷。
   - 判停条件: 无，结束。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 账号已经被盗、正在被顶下线，需要判断先改密、先冻结还是先申诉：先用 `account-compromise-layering`，本 skill 不提供止损顺序。
- 问题已经明确是“普通用户能读改他人对象”，只需要对象级授权检查：走 `access-control-and-idor`。
- 问题集中在接口批量赋值、GraphQL introspection、Swagger 暴露、接口限流：走 `api-and-interface-security`。
- 只有一张登录页截图、没有响应头、没有账号、没有配置，无法观察会话行为：只能做静态核查清单，不能给出“认证不安全”的确定结论。
- 目标是破解口令、绕过他人 MFA、伪造他人令牌：不属于防御性审查范围。

### 作者在书中警告的失败模式
- 本清单未覆盖“登录成功即认证安全”的误判：能登录只说明主路径通，不能说明会话轮换、注销撤销、MFA 绑定和找回密码链路正确。
- 本清单未覆盖“只看 Cookie 标志、不看服务端会话”的失败：标志齐全但注销不销毁会话，仍然是有效漏洞。
- 本清单未覆盖“把 JWT 当不可篡改”的失败：不验签、不固定算法、盲信角色声明，都会把令牌变成越权入口。
- 本清单未覆盖“只测 OAuth 登录成功、不测 state/PKCE/redirect_uri”的失败：主流程成功恰恰最容易掩盖回调劫持。
- 本清单未覆盖“把 SSO 配置当一次性工作”的失败：证书轮换、元数据更新、注销传播和账号映射漂移都会重新打开信任缺口。

### 作者的盲点 / 时代局限
- 本清单未覆盖 WebAuthn/passkeys 的 attestation、设备绑定、同步凭据与降级攻击，也未覆盖持续认证和风险自适应认证。
- 本清单未覆盖令牌绑定、DPoP、mTLS 客户端认证等把会话与传输通道绑定的机制。
- 本清单未覆盖跨协议联邦注销、SCIM 供应、账号生命周期自动化与多 IdP 并存时的映射冲突。
- 本清单未覆盖认证日志、异常登录检测与监控告警的运营侧要求；这些应与日志与漏洞管理类 skill 组合使用。
- 标准与协议持续演进，具体参数名和默认值应以目标版本的一手文档为准，本清单不替代协议规范。

### 容易混淆的邻近方法论
- `account-compromise-layering`：处理“已经被盗之后先做什么”，本 skill 处理“认证与会话实现是否可信”。
- `access-control-and-idor`：处理“认证之后能访问什么”，本 skill 处理“身份如何建立、会话如何维持”。
- `api-and-interface-security`：按接口逐点检查认证、授权、输入输出与限流，本 skill 只深入令牌与会话机制。
- `client-side-and-frontend-security`：处理浏览器侧令牌存储、CSRF、CORS，本 skill 处理 Cookie 属性语义与服务端会话。
- `email-trust-boundary`：判断邮件是否可信，本 skill 只把邮件/短信当作验证码通道来审。
- `pentest-engagement-and-disclosure`：先定授权与边界，本 skill 的主动对照实验必须在其约束下进行。
