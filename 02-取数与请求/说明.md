# 02 取数与请求

## 这一类管什么

把"我在浏览器里看到这条数据"变成"脚本能稳定拿到这条数据"：复现一次请求、找到页面自己用的接口、把参数删到最小、处理需要等待的异步会话。

## 什么时候进这里

- 已经确认要抓（合规与路径已过），卡在"请求怎么写"。
- 表单提交没反应、登录后还是未登录、响应格式不对。
- 页面数据是空的，但浏览器里有。
- 扫码登录、回调、轮询这类"要等对方动作"的流程。

## 什么时候不该进来

- 请求发出去就被 403/白页 —— 先去 `03-反爬对抗与逆向/01-通道与封禁` 分诊，别在这里反复改参数。
- 参数明显是加密串（sign/token）且找不到生成处 —— 转 `03-反爬对抗与逆向/03-Web参数定位`。
- 已经拿到 HTML，只是解析不出来 —— 转 `05-解析与数据/01-选择器与抗改版`。

## 子类

### `01-单请求复现`
把浏览器里那一次成功请求，一比一抄成脚本能跑的请求；以及处理表单里的一次性隐藏字段。
包含 `http-request-replication`、`form-hidden-state-and-readback`。

### `02-接口与表格`
页面数据不在 HTML 里时，找站点自己的 JSON 接口；拿到接口后先删参数；无文档系统的 API 逐个复刻成表。
包含 `api-table-replication`、`page-owned-api-recon`、`dynamic-page-and-min-params`。

### `03-异步会话`
出码 → 等人操作 → 轮询状态 → 换令牌 → 带令牌调用，这一整套。
包含 `qr-poll-session`。

## 类内推荐顺序

1. 先 `http-request-replication` 打通一条请求（含隐藏字段与 Cookie 罐）。
2. 若数据不在响应体里，`dynamic-page-and-min-params` 判动态页 + 找 XHR + 删参数。
3. 若目标是整套无文档系统，`api-table-replication` 把每个请求抄成一行再串主循环。
4. 若流程要等对方（扫码/审批/支付），`qr-poll-session`。

## 常见走错路径

- 一遇空白页就上浏览器：先 `page-owned-api-recon` / `dynamic-page-and-min-params` 看页面自己调了什么。
- 请求 403 先加 UA/Referer：很多时候是**多带了参数**，先删再查身份。
- 登录成功就以为有会话：必须回读一个需要登录的页面做断言。
