# 02 成本与路径

## 解决什么

同一份数据往往有五条以上的拿法，价钱差一个数量级。这个子类给两条阶梯：**取数路径的阶梯**（从最便宜的入口往上试）和**逆向投入的阶梯**（到哪一级就该停），外加一个"请求库 / 浏览器 / 隐身浏览器"的档位判定。

## 触发信号（用户原话）

- "这个站的数据该怎么取 / 用不用 Selenium"
- "页面抓下来是空的，是不是要上浏览器"
- "有打印版吗 / 有没有内部接口"
- "这个逆向值得做吗 / 要不要脱壳"
- "这套工具能不能搞定这个站"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `data-path-cost-ladder` | 按成本逐级试：打印版/移动版 → JS 内嵌数据 → URL slug → 换源 → 改请求头拿简化版 → 页面自用 JSON 接口 → 浏览器执行 JS | 权威指南 2e | 决定取数方案、或页面空白/残缺时 |
| `fetch-tier-triage` | 按「是否必须 JS 渲染 × 是否已被检测」两轴定档（请求库 / 浏览器 / 隐身浏览器），并给能力边界 | Scrapling 文档 | 上线前评估"这个工具够不够" |
| `reverse-cost-ladder` | 承认逆向有终点，按成本由低到高：换载体/拦截 → 自动化 → RPC → 复写/补环境 → 脱壳/Unidbg，每级预设退出条件 | 逆向进阶实战 | 纠结"要不要脱壳/值不值得逆"时 |

## 类内先后

1. `data-path-cost-ladder` —— 先确认有没有不写解析器的便宜入口。
2. `fetch-tier-triage` —— 便宜入口都不可用时，定"请求库 / 浏览器 / 隐身浏览器"哪一档，以及这一档能不能闭环。
3. `reverse-cost-ladder` —— 只有必须碰加密/加固时才用，用来决定停在哪一级。

## 不该在这里解决

- 已经被封、要定位是哪一层拦的 —— 转 `03-反爬对抗与逆向/01-通道与封禁`。
- 已经定位到加密函数、要判断复现对不对 —— 转 `03-反爬对抗与逆向/03-Web参数定位`。
- 只是选择器写错 —— 转 `05-解析与数据/01-选择器与抗改版`。

## 内容速览

- 阶梯的价值在**顺序**：先试不花钱的，再试花时间的，最后才试要逆向的。多数人从最难的一级开始。
- 定档的两轴是"必须 JS 渲染"和"已被检测"，不是"站点名气大小"。
- 逆向每一级都要**预设退出条件**（到某个时间点或某条判据就放弃），否则会无限下沉。

## 使用示例

### 示例 1：正文抓不到，要不要上浏览器
**用户说**：「这个新闻站的文章正文抓下来是空白，是不是得装 Selenium？」

**路由**：`data-path-cost-ladder` —— 先花五分钟走阶梯，再决定要不要引入浏览器这一整层成本。

**执行**（逐级，命中即停）：
1. 试 `/print`、`/amp`、移动版 URL —— 很多站直接给全文。
2. 在 HTML 里搜正文第一句话 —— 搜到说明是内嵌 JSON 或转义字符串，解开即可。
3. 看 URL 是否含 article id —— 有就试拼接口。
4. 换移动端 UA 拿简化版。
5. 找页面自己发的 XHR（见 `02-取数与请求/02-接口与表格`）。
6. 以上全失败，才进浏览器。

**产出**：例："打印版返回全文，正文在 `<div class=article>` 里" —— 直接省掉浏览器层；或"五级都失败，按 `fetch-tier-triage` 定浏览器档位"。

### 示例 2：这套逆向值不值得做
**用户说**：「App 的 sign 一直算不出来，是不是得脱壳？」

**路由**：`reverse-cost-ladder` —— 先回答"值不值、停在哪一级"，再谈技术实现。注意 `fetch-tier-triage` 不适用于这里（它只判 Web 抓取档位）。

**执行**：从最低一级往上核：能不能拦截已经算好的请求 → 能不能自动化点击 → 能不能用 RPC 直接调用 → 能不能只复写签名那一段 → 最后才是脱壳/Unidbg。

**产出**：一条带退出条件的结论，例："先用 Frida RPC 导出接口，两周内不能稳定产出就停，不脱壳。"
