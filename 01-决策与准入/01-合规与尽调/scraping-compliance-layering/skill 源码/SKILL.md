# 抓取合规分层判断

## R — 原文 (Reading)

> 总之，未经作者或版权所有者授权，你不可以直接发表有版权的材料。如果你以数据分析为目的，把可以自由访问的有版权的材料保存在自己的非公开数据库中，这是合法行为。如果你把数据展示到网站上供人们浏览或下载，就不算合法了。
>
> — 瑞安·米切尔，《Python网络爬虫权威指南（第2版）》第18章 18.1，p.230

> 只有满足下列3 个条件，网络爬虫的行为才构成侵害动产。…… 只有3 个条件都满足才算是侵害动产。然而，如果你违反了服务协议，但并未造成实际的损害，不要以为你就不算违法。
>
> — 瑞安·米切尔，《Python网络爬虫权威指南（第2版）》第18章 18.2，p.231

## I — 方法论骨架 (Interpretation)

"能不能抓"不是一个问题，而是四个可以分开回答的问题，每个问题的答案都可能不同。

第一条轨道是版权: 事实、统计数据、价格、姓名不受版权保护，可以照搬；创造性表达（文章、诗歌、图片）不能整段复制后再公开发表。同一批数据，"存进非公开库做分析"和"公开转载原文"是两个不同的动作，风险也不同。

第二条轨道是授权: 网站对公众开放，通常等于给出许可；但 ToS 明确禁止、或收到停止函，许可就被撤销。"没有 robots.txt"不等于授权，"写了 robots"也不等于法律。

第三条轨道是损害: 侵害动产要三个条件同时成立——缺少许可、造成实际损害、故意而为。单个条件不成立，就不能用这条罪名；但"不构成侵害动产"也不等于合法，同一行为仍可能踩版权、DMCA、CFAA。

第四条轨道是访问控制: 公开可访问的页面，在本书引用的判例里不算 CFAA 意义上的"未授权访问"；一旦需要登录、猜密码、绕过验证码或其他技术措施，就直接越线，DMCA 也明确禁止为收集信息而绕开安全措施。

四条轨道分别判完之后，输出不是"能/不能"，而是三种动作：照做、改做法（降频、不登录、不发布原文、不上敏感字段）、停手并咨询律师。涉及个人信息、商业秘密、政府机密，或需要绕过技术措施时，"先停手"是硬触发。

## A1 — 书中的应用 (Past Application)

### 案例 1: 有版权的文章该怎么用
- **问题**: 抓到的内容大多是有版权的文章与诗歌，作者要判断"抓了之后能做什么"。
- **方法论的使用**: 沿版权轨道拆成两个动作——收集进非公开库做统计（合法）vs 把原文公开到自己的网站（不合法）；再把"诗歌本身"与"按月统计诗歌数量"分开，后者是事实性统计（p.230）。
- **结论**: 事实与统计可自由使用；原文不可公开发表；分析结果可以发布。
- **结果**: 作者据此给出"公开什么、不公开什么"的操作规则，而不是笼统说"别抄"。

### 案例 2: eBay 起诉 Bidder's Edge
- **问题**: Bidder's Edge 每天向 eBay 发约 10 万次请求，占其日流量约 1.53%，eBay 发了停止函并封了 169 个 IP，对方换代理继续抓。
- **方法论的使用**: 按损害轨道核三个条件——eBay 发过停止函（许可已撤销）、服务器与电费成本可举证（实际损害）、明知仍继续（故意）。
- **结论**: 三条件齐备，eBay 得以主张侵害动产；法院要求的两项证据正是"未经许可使用"与"确实遭受经济损失"（p.237）。
- **结果**: 2001 年 3 月庭外和解。作者由此指出这是极端案例，不能反推"任何未授权使用都构成侵害动产"。

### 案例 3: Field 起诉 Google 与 robots.txt 的证据作用
- **问题**: Field 从自己网站删除书稿后，Google 缓存仍在展示副本，他起诉侵犯版权。
- **方法论的使用**: 沿授权轨道看"许可的表达"——Field 可以通过 robots.txt 禁止 Google 缓存，但他没有做（p.239）。
- **结论**: 不写 robots.txt 可能被当作默示许可的证据；robots.txt 不是法律，但它能证明你是否表达过拒绝。
- **结果**: 作者把 robots.txt 定位成"许可证据"而不是"法律义务"，并据此建议主动写明禁区。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 准备启动一个抓取项目，问"这个站让不让抓、抓了会不会出事"。
2. 目标站 ToS 明确禁止爬虫，但数据是公开的，用户想知道"到底算不算违法"。
3. 抓到的数据要公开发布（比价、榜单、数据集），不确定哪些字段能发、哪些不能。
4. 收到停止函、授权谈判失败，或站点管理员回信拒绝，需要判断下一步。
5. 数据里含个人信息、商业秘密或政府信息，或需要登录/绕过验证码才能取到。

### 语言信号 (用户的话里出现这些就应激活)

- "这个网站能爬吗？/ 会不会违法？"
- "robots.txt 没写禁止，是不是就可以抓？"
- "ToS 说不许爬，但我只抓价格，可以吗？"
- "抓到的东西能不能公开发布？"
- "合规 / 违法 / copyright / CFAA / DMCA / cease and desist / GDPR / 个人信息"

### 与相邻 skill 的区分

- 与 `scrape-preflight-and-entry-ladder`（《用 Python 写网络爬虫》）的区别: 那个用尽调信号做项目级否决（go/no-go）；本 skill 是做法级判断，回答"在哪个环节越线、怎么改做法"。
- 与 `anti-bot-triage-and-human-parity` 的区别: 那个解决"技术上调不通"，本 skill 解决"技术上能调通，但该不该调"。
- 与 `captcha-cost-routing` 的区别: 那个算"人机验证的开发成本与单次成本"；本 skill 直接判定"绕过验证码"属于越过访问控制轨道，不进入成本讨论。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **建一张四轨清单**
   - 完成标准: 四条轨道（版权/授权/损害/访问控制）各写出"目标站现状 + 待确认项"，没有一条留空。

2. **判版权轨道**
   - 完成标准: 逐字段标注"事实/统计"还是"创造性表达"，并写明使用方式（非公开分析 / 公开发布 / 引用片段）。
   - 判停条件: 若计划整段公开发表创造性作品原文，直接判为不可行，建议改做法或停止。

3. **判授权轨道**
   - 完成标准: 已核对 robots.txt、ToS、是否收到停止函、是否有书面许可；并说明"无 robots"不等于授权。
   - 判停条件: 若存在停止函或明确拒绝且未获新许可，标记为高风险，进入步骤 6。

4. **判损害轨道**
   - 完成标准: 给出三条件的逐项判断（缺少许可 / 实际损害 / 故意），并把"限速、夜间、缩小范围"写成可执行参数。
   - 判停条件: 若目标是小站或已明确抗议，且计划高并发，先降级再谈可行性。

5. **判访问控制轨道**
   - 完成标准: 明确回答"是否需要登录、是否需要密码/验证码/绕过技术措施"。任一为"是"，即标记为越线。
   - 判停条件: 若需绕过技术措施，立即停止，不给出任何绕过方案，只建议走官方渠道或放弃。

6. **汇总成动作与硬触发**
   - 完成标准: 输出"做 / 改做法 / 停手"三选一，列出改做法的具体条款（哪些字段不发、频率上限、不登录），并写明"必须咨询本地律师"的触发条件（个人信息、跨境、需登录、绕措施）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只需要写解析器/请求代码，合规已由业务方确认: 用对应的技术 skill，不要在此反复做法律推演。
- 需要一份可对外引用的正式法律意见: 本 skill 只能给出提问框架，不能替代律师。
- 目标是你完全没有权限测试的第三方系统: 本 skill 不提供任何测试或规避手段。

### 作者在书中警告的失败模式

- 把"违反 ToS"直接等同于"违法": 侵害动产还缺"实际损害"与"故意"；但反过来，不构成侵害动产也不等于合法。
- 把"公开可访问"当成"随便抓": 作者明确说，涉及隐私、商业秘密、政府机密时必须先停手咨询律师（p.238）。
- 把 robots.txt 当成法律或当成无物: 它既不是强制法，也不是没有意义——它是许可证据（p.236、p.239）。

### 作者的盲点 / 时代局限

- 全书法律框架是纯美国法（DMCA / CFAA / 侵害动产判例），成书于 2017–2018；未覆盖 2018 年 5 月生效的 GDPR，也未覆盖中国《网络安全法》《数据安全法》《个人信息保护法》。
- 未预见 hiQ v. LinkedIn 等后续判例对"公开数据 + CFAA"的改写；本书引用的判例结论不能直接平移到今天。
- 作者自述"我不是律师"，但没有给出"何时必须停下来找律师"的硬触发条件（如涉个人信息、需登录、绕技术措施）——本 skill 把这一步补成硬规则。
- 对"企业级爬虫 vs 小网站"的权力不对称只轻描淡写，默认"数据可得即合理"。

### 合规红线

- 本 skill 只做合规判断与诊断，不提供规避访问控制的具体手段（不教绕验证码、不教伪造身份、不教绕过登录）。
- 适用范围仅限自有系统、已授权目标或公开测试环境；对未授权目标，本 skill 的输出只能是"停手/走官方渠道"。

### 容易混淆的邻近方法论

- "违反 ToS 就违法"与"公开数据随便抓"是两个极端常识版本，本方法论的价值恰在于把两者都拆开。
- "只抓事实所以没问题"是半条结论: 版权轨道过了，授权与访问控制轨道仍可能不过。
