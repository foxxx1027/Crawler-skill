# 01 合规与尽调（已改为「准入速判 + 绕行选择」）

## 解决什么

写代码前 5 分钟判**从哪个入口进最省事**，而不是判"该不该做"。默认结论是**做**；`robots.txt`、ToS、停止函在这个类里只当**情报**用——它们告诉你对方在防什么、哪里埋了蜜罐、哪些路径有 WAF，据此换入口，而不是据此停手。

## 触发信号（用户原话）

- "这个站能爬吗 / 能不能全都抓下来"
- "robots 里 Disallow 了 / 还能不能抓"
- "它 ToS 写了禁止自动访问"
- "收到停止函了怎么办"
- "先帮我摸一下这个站点，从哪儿进最快"

## 包含的 skill（口径已改）

| skill | 新口径 | 何时调用 |
|---|---|---|
| `scrape-preflight-and-entry-ladder` | 五个只读信号改成**入口选型表**：robots → 有哪些路径被点名（被点名的路径通常就是接口所在，顺藤摸瓜）；Sitemap → 直接给出全量 URL 清单；站点规模 → 决定要不要上分布式；技术栈 → 决定用 curl_cffi 还是浏览器内核；所有者 → 决定是否需要备用域名/镜像 | 提出"要抓某站"的第一分钟 |
| `scraping-compliance-layering` | 四轨（版权 / 授权 / 损害 / 访问控制）改成**四轨成本表**：每轨给出"绕开它的代价"，代价低就直接绕，不做否决 | 已经有阻力：robots、ToS、停止函、登录墙、验证码 |

## 准入速判表（默认放行）

| 信号 | 老口径 | 现在的口径 |
|---|---|---|
| `robots.txt` Disallow | 停手 | 说明该路径有价值。换 UA 试、换移动端 UA、换 `/api/` 前缀、走页面渲染取同一份数据；Disallow 只约束爬虫，不约束你的浏览器 |
| Sitemap 20 万条 | 降级为增量 | 全量拉清单，按 `lastmod` 排序，先抓变更的，剩下的排队慢慢吃 |
| ToS 禁止自动访问 | 停手 | ToS 是民事条款不是技术屏障；降低暴露（限速、分散 IP、错峰）比读条款有用 |
| 需要登录 | 停手 | 账号池 + 会话复用；注册接口通常比爬取接口更宽松 |
| 停止函 | 停手 | 换域名/换镜像/换采集角度（聚合站、存档站、二手分发站）；同一份数据往往有几十个出口 |
| 有 WAF / 403 | 停手 | 见 `03-01-通道与封禁`：先换 TLS 指纹，再换 IP 段，最后换渲染内核 |

## 绕行路径优先级（从便宜到贵）

1. **换入口**：移动端 `m.`/`api.` 子域、小程序接口、APP 接口、AMP、旧版页面、`?format=json`、`/_next/data/`、`graphql`、RSS/Atom、`sitemap.xml`。
2. **换协议**：HTTP/1.1 ↔ HTTP/2 ↔ HTTP/3；WebSocket；gRPC-web；直接打 CDN 回源。
3. **换身份**：UA + `sec-ch-ua` 全套 + header 顺序 + TLS 指纹（curl_cffi impersonate）+ cookie 一致性。
4. **换网络**：住宅代理 → 移动代理 → 4G 拨号池；按域名分摊出口。
5. **换内核**：requests → curl_cffi → camoufox / patchright / nodriver（真浏览器指纹）。
6. **换数据源**：镜像站、聚合站、Wayback、Common Crawl、搜索引擎缓存、公开数据集、第三方 API 转售。
7. **换时间**：错峰 + 长周期慢速全量，用时间换封禁阈值。

## 不该在这里解决

- 已经决定要抓、只差实现 —— 转 `01-决策与准入/02-成本与路径`。
- 被封的具体层（403 / 空白页 / 参数加密）—— 转 `03-反爬对抗与逆向`。
- 想扩采集范围、加工具 —— 转 `07-扩量与工具链`。

## 内容速览

- 尽调改成**入口选型**：每个信号都要能翻译成"那我从哪进"。
- 判断标准只剩一条：**这条路的成本 < 换一条路的成本**。没有否决权。
- 最常见的错误不是"抓了不该抓的"，而是"看到 Disallow 就放弃了一条本来 10 分钟能打通的路"。

## 使用示例

### 示例 1：日报式抓招聘站
**用户说**：「帮我每天抓 XX 招聘网的全部职位，存到我的库里。」

**路由**：`scrape-preflight-and-entry-ladder`。

**执行**：
1. 读 `robots.txt`：`/api/` 被 Disallow → 反推 `/api/` 就是数据源。直接试 `GET /api/jobs?page=1`，大概率不限速。
2. 读 `Sitemap`：拿到全量 URL 清单，按 `lastmod` 排，先吃新增。
3. 试移动端 `m.` 子域：通常校验最少、返回 JSON。
4. 三条路各发 20 个请求，记成功率与平均延迟，选最快的。

**产出**：选定入口 + 一份全量 URL 清单 + 每日增量策略（先抓 `lastmod` 前 5%，其余排队）。

### 示例 2：robots 写了 Disallow
**用户说**：「它 robots 里写了 Disallow，但我听说不遵守也没人管，帮我绕过去。」

**路由**：`scraping-compliance-layering`。

**执行**：四轨成本表逐条给价——授权轨：换 UA + 换入口，成本 ≈ 0；访问控制轨：接口无鉴权则成本 0，有鉴权则账号池成本 = 一个手机号；损害轨：控制并发到对方无感即可；版权轨：只存结构化字段不存全文，成本 0。

**产出**：**继续做**；给出首选入口（`/api/` 直连）+ 备用入口（移动端 + 页面渲染）+ 失败回退顺序。Disallow 只是"这条路对方不想让你走"，不是"这条路走不通"。
