# 02 单点还原

## 解决什么

五种常见混淆手法的**单点**还原动作。它们都建立在"已经判过层、知道要动哪一步"的前提上；单独用其中一个，前提是先知道当前卡在哪一种。

## 触发信号（用户原话）

- "文件开头一大坨字符串数组 / 换明文后 undefined"
- "代码块顺序错乱 / split('|') 分发器"
- "老从同一个对象上按属性名套娃取值"
- "425871^425977 / \u4e2d / eval(atob()) 这种值"
- "满屏下划线变量名，批量改名后值偏了"

## 包含的 skill

| skill | 手法 | 一句话做法 | 来源 |
|---|---|---|---|
| `string-pool-decrypt-revive` | 字符串池 | 大数组+乱序自执行+解密函数三段进空 AST → compact → 沙箱 eval → 只换 `CallExpression` 引用 → 按路径删三段 | 反爬虫AST |
| `control-flow-flattening-restore` | 流程平坦化 | 先取分发器（`split('|')` 置换表），再 findParent 取循环、getSibling 取 switch、按 cases 清 body 重排；嵌套单步收敛 | 反爬虫AST |
| `junk-instruction-elimination` | 套娃取值 | 分字符串链/函数包装建 totalObj，先改定义侧重算、再改引用侧，引用清零才删对象 | 反爬虫AST |
| `constant-fold-and-decoding` | 常量与编码 | evaluate 且 confident 才 valueToNode；eval/fromCharCode 把解密函数搬本地跑；转义用 minified+jsescOption | 反爬虫AST |
| `scope-safe-rename` | 标识符改名 | `getOwnBinding` 带出子函数绑定并按 `binding.scope` 过滤归属，收自由名避撞，`scope.rename` 后 generate→parse 重建 | 反爬虫AST |

## 类内顺序

按总装的段序走，不要按手感挑：

```
字符串池 → 花指令（套娃/常量/编码）→ 平坦化 → 改名
```

- 字符串必须最先：后续所有定位都依赖"按明文搜索"。
- 改名必须最后：改名之后"按属性字符串搜索"这条线索就断了。
- 平坦化在改名之前：重排需要按 case 结构找块，改名不影响结构但会增加阅读负担。

## 相互边界（容易抢调用）

| 现象 | 归属 | 不要给谁 |
|---|---|---|
| 纯算式 / 转义 / `eval(atob())` | `constant-fold-and-decoding` | 不是 `junk-instruction-elimination` |
| 同一对象按属性名层层取值 | `junk-instruction-elimination` | 不是 `constant-fold-and-decoding` |
| 整池字符串编号调用 | `string-pool-decrypt-revive` | 不是零散的常量折叠 |
| 分发器被对象取值包住（如 `_0x22b277['xYz'].split('|')`） | **先** `junk-instruction-elimination` 取出 `'xYz'`，**再** 回 `control-flow-flattening-restore` | 这是本类已知的边界冲突点，见下 |

> 已知缺口：`control-flow-flattening-restore` 的 B 段把"分发器被对象取值包住"判给了 `junk-instruction-elimination`，与其测试用例 `should-trigger-04` 存在冲突。实操时按上表的两步走，不要二选一。

## 不该在这里解决

- 还没判层、不知道有哪几种手法 —— 回 `01-判层与总装`。
- 整条流水线顺序怎么排 —— 回 `01-判层与总装` 的 `ast-restore-pipeline-acceptance`。
- 补运行环境 —— 转 `03-反爬对抗与逆向/03-Web参数定位` 的 `js-env-patch-loop`。

## 内容速览

- 字符串池三个必踩坑：删错引导代码（会自毁）、忘 compact（触发格式化检测与 OOM）、把属性引用当调用点。
- 平坦化的第一步永远不是找 switch，而是先拿分发器串。
- 改名失败"能跑但值偏"的根因：绑定归属没按 scope 过滤。

## 使用示例

### 示例 1：字符串换成明文后 undefined
**用户说**：「我把开头的字符串数组手动替换成明文了，结果一运行就 undefined。」

**路由**：`string-pool-decrypt-revive` —— 典型的手工替换破坏了"调用点与定义"的对应。

**执行**：
1. 定位三段：大数组、乱序自执行函数、解密函数，**记录各自的 path**（不要按下标 shift）。
2. 把三段复制进 `parse('')` 的空 AST，生成可执行串。
3. 用 `compact: true` 生成（必做：原文可能带格式化检测与内存爆破）。
4. 沙箱 `eval` 得到"索引 → 明文"映射。
5. 只替换 `parentPath.isCallExpression` 的引用（属性引用不是调用点）。
6. 按记录 path 逐段删除。

**产出**：明文版 JS + 变更清单（替换了多少处、删了哪三段）。

### 示例 2：分发器被对象取值包住
**用户说**：「分发器不是字符串字面量，是 `_0x22b277['xYz'].split('|')`，平坦化脚本认不出来。」

**路由**：两步走 —— 先 `junk-instruction-elimination` 把 `'xYz'` 还原成实际字符串并替换引用，再回 `control-flow-flattening-restore` 取分发器、找 `while`、按 cases 重排。
