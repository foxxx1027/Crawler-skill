# 02 采集面扩展

## 解决什么

列表页通常只暴露全站 5%～20% 的内容。这一子类给**十种把采集面撑开的办法**和现成代码，目标是把"抓到 3 万"变成"抓到 80 万"，且不去碰加密参数。

## 触发信号（用户原话）

- "只翻到第 10 页就不给翻了"
- "搜索只显示 1000 条"
- "整站有 50 万，我只能抓到 3 万"
- "列表页没分类的怎么抓"
- "站点关了/删了，还能弄到吗"

## 十个扩面手段（按性价比排序）

| # | 手段 | 打穿的是什么限制 | 典型增量 |
|---|---|---|---|
| 1 | Sitemap 递归 | 列表页分页上限 | 一次拿全站 URL，×10 起 |
| 2 | ID 空间遍历 | 列表页只展示"精选" | 拿到未上架的详情页，×N |
| 3 | 时间切片 | 结果集条数上限（1000 条天花板） | ×无限（按天/小时切） |
| 4 | 排序切片 | 同上，用另一维度绕过 | ×排序维度数 |
| 5 | 关键词枚举 | 未分类 / 长尾内容 | 补齐剩余 30%～50% |
| 6 | 分类树全叶子 | 只抓了一级分类 | 深层页 ×3 |
| 7 | 关联图遍历 | 孤立页（无入口链接） | 连通分量全覆盖 |
| 8 | 站点变体 | 单入口风控 | `m.` / `api.` / AMP / 旧版，成功率 ×2 |
| 9 | 分页游标三试 | `page` 被封 | `offset` / `cursor` / `since_id` 总有一个能用 |
| 10 | 存档兜底 | 站点删数据 / 关站 | Wayback + Common Crawl 补历史 |

## 1. Sitemap 递归（先跑这个，最划算）

```python
import gzip, io, re
from urllib.parse import urljoin
from curl_cffi import requests as creq

NS = "{http://www.sitemaps.org/schemas/sitemap/0.9}"
SESS = creq.Session(impersonate="chrome124")

def get_xml(url):
    r = SESS.get(url, timeout=30)
    if r.status_code != 200:
        return None
    body = r.content
    if url.endswith(".gz") or body[:2] == b"\x1f\x8b":
        body = gzip.GzipFile(fileobj=io.BytesIO(body)).read()
    return body.decode("utf-8", "ignore")

def walk_sitemap(url, seen=None, out=None, depth=0):
    seen = seen if seen is not None else set()
    out = out if out is not None else []
    if url in seen or depth > 5:
        return out
    seen.add(url)
    xml = get_xml(url)
    if not xml:
        return out
    locs = re.findall(r"<loc>\s*(.*?)\s*</loc>", xml)
    if "<sitemapindex" in xml:
        for child in locs:
            walk_sitemap(urljoin(url, child), seen, out, depth + 1)
    else:
        out.extend(urljoin(url, loc) for loc in locs)
    return out

def bootstrap_sitemaps(base):
    """robots 里的 Sitemap + 常见位置，一个都不放过"""
    cands = [urljoin(base, p) for p in (
        "/sitemap.xml", "/sitemap_index.xml", "/sitemap-index.xml",
        "/sitemap1.xml", "/sitemap.xml.gz", "/sitemaps/sitemap.xml",
        "/wp-sitemap.xml", "/news-sitemap.xml",
    )]
    robots = SESS.get(urljoin(base, "/robots.txt"), timeout=20).text
    cands += re.findall(r"(?im)^sitemap:\s*(\S+)", robots)
    urls = []
    for c in dict.fromkeys(cands):
        urls += walk_sitemap(c)
    return list(dict.fromkeys(urls))
```

## 2. ID 空间遍历（列表页之外的详情页）

```python
import concurrent.futures as cf

def probe_id(base_detail, i, sess):
    url = base_detail.format(id=i)
    try:
        r = sess.get(url, timeout=15, allow_redirects=False)
        return i, r.status_code, len(r.content)
    except Exception:
        return i, 0, 0

def sweep_ids(base_detail, lo, hi, workers=64):
    """base_detail 例：'https://<PH:target>/item/{}'
    判活：200 且长度与其他有效页同量级；软 404 需比对页面特征词"""
    sess = creq.Session(impersonate="chrome124")
    hits = []
    with cf.ThreadPoolExecutor(workers) as pool:
        futs = [pool.submit(probe_id, base_detail, i, sess) for i in range(lo, hi)]
        for f in cf.as_completed(futs):
            i, code, size = f.result()
            if code == 200 and size > 5000:
                hits.append(i)
    return sorted(hits)
```

先从一个已知详情页取 `id` 的量级与步长，再分段跑；软 404（永远 200）要先用 3 个不存在的 id 采样出"空页长度基线"。

## 3. 时间切片（打穿 1000 条天花板）

```python
from datetime import date, timedelta

def day_slices(start, end):
    d = start
    while d <= end:
        yield d.isoformat(), (d + timedelta(days=1)).isoformat()
        d += timedelta(days=1)

def adaptive_split(query_fn, lo, hi, min_window=1):
    """query_fn(start, end) 返回条数。到上限就二分，直到条数 < 上限"""
    n = query_fn(lo, hi)
    if n < LIMIT:
        return [(lo, hi)]
    s, e = date.fromisoformat(lo), date.fromisoformat(hi)
    if (e - s).days <= min_window:
        return [(lo, hi)]
    mid = (s + (e - s) / 2).isoformat()
    return adaptive_split(query_fn, lo, mid) + adaptive_split(query_fn, mid, hi)
```

同一份逻辑套到任何"按维度筛选"的接口：`price_range`、`area`、`category`、`brand`。

## 4. 排序切片 + 5. 关键词枚举

```python
SORTS = ["time_desc", "price_asc", "price_desc", "hot", "new"]
KEYS  = ["<PH:kw1>", "<PH:kw2>", "<PH:kw3>"]  # 行业词典 200～2000 个

def union_urls(build):
    seen = {}
    for s in SORTS:
        for kw in KEYS:
            for url in build(sort=s, kw=kw):
                seen.setdefault(url, 0)
                seen[url] += 1
    return list(seen)
```

合并后把"被多个切片命中"的 URL 排前面先抓，只被命中一次的丢到低优先级队列。

## 6. 分类树全叶子

```python
def crawl_categories(root_url, link_sel=".cat a", sess=None):
    sess = sess or creq.Session(impersonate="chrome124")
    queue, leaves, seen = [root_url], [], set()
    while queue:
        u = queue.pop(0)
        if u in seen:
            continue
        seen.add(u)
        html = sess.get(u, timeout=20).text
        subs = extract_links(html, link_sel)          # 只取分类链接
        (queue.extend(subs) if subs else leaves.append(u))
    return leaves
```

叶子清单拿到后再逐叶翻页，比"整站 BFS"命中率高得多，也不容易被判定为目录爆破。

## 7. 关联图遍历

详情页里的"相关推荐 / 同店 / 同标签 / 猜你喜欢"是天然的边。用 BFS 从种子集合扩散，去重后通常能覆盖整个连通分量——包括没有任何列表入口的孤立页。

```python
def graph_walk(seeds, parse_related, max_nodes=10**6):
    seen, queue = set(seeds), list(seeds)
    while queue and len(seen) < max_nodes:
        u = queue.pop()
        for v in parse_related(u):
            if v not in seen:
                seen.add(v)
                queue.append(v)
    return seen
```

## 8. 站点变体（同一份数据的多个出口）

```
https://<PH:target>/          → 主站
https://m.<PH:target>/        → 移动端，校验最松
https://api.<PH:target>/      → 接口，通常无 UI 层风控
https://<PH:target>/amp/xxx   → AMP，静态且干净
http://<PH:target>/           → 明文 http，有时命中旧 WAF 规则
https://<PH:target>/zh-cn/    → 多语言子路径，数据相同
https://static.<PH:target>/   → 静态 JSON 底座（前端直取）
```

判断方法：一个详情页在 7 个变体各请求一次，比 body 长度与关键字段，选返回最全、校验最少的那个。

## 10. 存档兜底（站点删了也能捞）

```python
# Wayback CDX：拿某域名所有历史 URL
# http://web.archive.org/cdx/search/cdx?url=<PH:target>/*&output=json&fl=original,timestamp&collapse=urlkey&limit=100000

# Common Crawl：按域名捞历史抓取记录（需查最新 index）
# https://index.commoncrawl.org/CC-MAIN-2024-<PH:index>-index?url=<PH:target>/*&output=json
```

```python
def wayback_urls(domain, limit=100000):
    api = ("http://web.archive.org/cdx/search/cdx"
           f"?url={domain}/*&output=json&fl=original,timestamp&collapse=urlkey&limit={limit}")
    rows = creq.get(api, timeout=120).json()[1:]
    # 优先取最新快照：https://web.archive.org/web/<ts>id_/<original>
    return [(ts, orig) for orig, ts in rows]
```

## 内容速览

- 扩面的顺序永远是：**Sitemap → 分类全叶子 → 时间/排序切片 → ID 空间 → 关联图 → 存档兜底**。
- 任何"只显示 N 条"的接口，都能用维度切片打穿；维度 = 时间、价格、地区、分类、品牌、排序。
- 站点变体是零成本的翻倍，先测 7 个变体再谈逆向。
- 软 404 必须先采样基线，否则 ID 爆破会把整站错误页当成有效数据入库。

## 使用示例

### 示例 1：只翻到第 10 页
**用户说**：「列表页翻到第 10 页就返回空了，但站里明显有几十万条。」

**路由**：本子类（1 + 3 + 9）。

**执行**：
1. 先跑 `bootstrap_sitemaps()`：多数站 sitemap 里就有全量 URL，直接跳过翻页问题。
2. 没有 sitemap → 试 `offset` / `cursor` 两种游标，看能不能翻过第 10 页。
3. 都不行 → 时间切片：`?start=2020-01-01&end=2020-01-02` 逐天取，天内还有上限就二分到小时。
4. 并发跑切片，结果按 URL 去重合并。

**产出**：全量 URL 清单（sitemap 优先，切片补齐）+ 一份"每个切片拿到多少条"的对账表，用总和校验是否漏。

### 示例 2：站点已经关停
**用户说**：「那个站去年就关了，我还想要它的商品数据。」

**路由**：本子类（10）。

**执行**：
1. Wayback CDX 拉全量历史 URL，`collapse=urlkey` 去重，按 timestamp 取最新快照。
2. Common Crawl index 交叉比对，补齐 Wayback 没收录的。
3. 快照页用 `id_` 后缀取原始 HTML（不带 Wayback 注入的工具栏）。
4. 批量抓取时对 `web.archive.org` 单独限速（它比目标站更脆）。

**产出**：历史全量 URL 清单 + 可解析的原始 HTML 集 + 每条的抓取时间点（用于判断数据新鲜度）。
