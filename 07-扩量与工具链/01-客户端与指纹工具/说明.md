# 01 客户端与指纹工具

## 解决什么

同一个 URL，不同客户端的手气完全不同。这一子类给一张**选型表 + 现成代码**，目标是让每个入口都有一个能打的客户端，而不是上来就 requests 撞 403。

## 触发信号（用户原话）

- "requests 一直 403 / 浏览器能开"
- "有没有不用 selenium 的方案"
- "怎么把 curl_cffi 接进 Scrapy"
- "Scrapling 怎么用 / 值不值得换"
- "Cloudflare 那关怎么过"

## 工具矩阵

| 工具 | 内核 | 扛什么 | 内存/速度 | 一句话 |
|---|---|---|---|---|
| `curl_cffi` | libcurl-impersonate | JA3/JA4 + HTTP2 指纹 | 极低 / 极快 | **默认首选**，90% 的 403 死在这 |
| `hrequests` | 同 curl_cffi | 上面 + 类 requests API + 内置浏览器兜底 | 低 / 快 | 想少写代码时用 |
| `tls-client` (Go) | Go tls 补丁 | 任意自定义 TLS 指纹 | 低 / 快 | 需要伪造特定客户端指纹时 |
| `Scrapling` | curl_cffi + Camoufox | `Fetcher` / `StealthyFetcher` / `DynamicFetcher` 三档 | 中 / 中 | 一个库覆盖三档，省选型 |
| `camoufox` | Firefox 定制 | Cloudflare 托管挑战、DataDome | 高 / 慢 | 重防护站的终局方案 |
| `patchright` | Chromium 补丁 | CDP 泄漏（`Runtime.enable`） | 高 / 慢 | playwright 用户的最小改动 |
| `nodriver` | Chromium + CDP | webdriver 特征、Cloudflare turnstile | 高 / 慢 | uc 作者新作，比 Selenium 干净 |
| `undetected-chromedriver` | Chromium | 老站、老 WAF | 高 / 慢 | 维护少了，优先 nodriver |
| `playwright + playwright-stealth` | Chromium | 轻量指纹补齐 | 高 / 慢 | 够用，但扛不住强风控 |

## 三档客户端，按站点强度选

```python
# 第 1 档：纯 HTTP + TLS 伪装（默认，覆盖 90%）
from curl_cffi import requests as creq

def fetch(url, proxy=None):
    return creq.get(url, impersonate="chrome124", proxies={"https": proxy} if proxy else None, timeout=20)
```

```python
# 第 2 档：Scrapling 三档切换，一个库打通
from scrapling.fetchers import Fetcher, StealthyFetcher, DynamicFetcher

def smart_fetch(url):
    r = Fetcher.get(url, impersonate="chrome")          # 快速：纯 HTTP
    if r.status == 200 and len(r.body) > 2000:
        return r
    r = StealthyFetcher.fetch(url, headless=True, network_idle=True)  # 中：Camoufox
    if r.status == 200:
        return r
    return DynamicFetcher.fetch(url, headless=True, network_idle=True)  # 重：真浏览器
```

```python
# 第 3 档：camoufox 硬刚托管挑战
from camoufox.sync_api import Camoufox

def hard_fetch(url):
    with Camoufox(headless=True, humanize=True, geoip=True, locale="zh-CN", os="windows") as page:
        page.goto(url, wait_until="domcontentloaded", timeout=60000)
        page.wait_for_timeout(3000)
        return page.content()
```

## 选型决策树

```
被拦了吗？没有 → curl_cffi
有 → 只换 impersonate 就通了吗？
     通 → curl_cffi + header 全套
     不通 → 是 Cloudflare/DataDome 挑战？
            是 → camoufox（Firefox）
            否 → patchright 或 nodriver（Chromium）
仍然不通 → 回到接口层：找 APP / 小程序 / 移动端接口，绕开 Web 风控
```

## 内容速览

- **客户端决定成功率，代理只决定封禁速度**。顺序别搞反。
- `impersonate` 要逐个试：`chrome124` / `chrome120` / `safari17_0` / `firefox133` / `edge101`，不同站认不同版本。
- 浏览器一定开 `persistent_context`（复用 profile），冷启一次成本极高。
- 打码是最后一步，且只对低成本挑战有意义；强风控站的解法是"别触发"。

## 使用示例

### 示例 1：把 requests 全换成 curl_cffi
**用户说**：「我这套爬虫全是 requests，现在大半站都 403，不想大改。」

**路由**：本子类 + `06-工程化与运行/02-速率与范围`。

**执行**：
1. 全局替换 `import requests` → `from curl_cffi import requests as requests`。
2. 每个请求点加 `impersonate="chrome124"`。
3. 统一注入 header 全套（参考 `03-01-通道与封禁`）。
4. 跑一批 100 个 URL 对比成功率，记下每个域认的 `impersonate` 版本。

**产出**：改动 3 行的迁移方案 + 每个域的成功率表 + 仍失败的域名清单（交给浏览器内核队列）。

### 示例 2：Cloudflare 一直转圈
**用户说**：「用 playwright 打开一直停在 Checking your browser。」

**路由**：本子类（第 3 档）。

**执行**：
1. 换 camoufox，`humanize=True`、`geoip=True`，UA/时区/语言跟 IP 对齐。
2. 开 `persistent_context` 复用 profile，第二次访问多数不再挑战。
3. 抓页面发出的 XHR，把真实接口拿回 HTTP 层重放（这一步才是收益点）。
4. 若接口带一次性 token，改用浏览器常驻 + 定时刷新 cookie 池。

**产出**：通过挑战的浏览器配置 + 从浏览器里捞出的一组可直接重放的接口（这才是真正扩量的部分）。
