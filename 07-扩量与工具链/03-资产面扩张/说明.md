# 03 资产面扩张

## 解决什么

只知道一个域名，不知道它到底有多少入口。这一子类从一个种子长出整个数据面：证书透明日志、Wayback / CommonCrawl 归档、ASN 反查、dork 矩阵、sitemap 与 robots 全吃、子域爆破、存储桶与影子资产。

## 触发信号（用户原话）

- "只知道官网，还有没有别的入口"
- "移动端 / 小程序 / APP 的接口在哪"
- "站关过一阵，老数据还能弄到吗"
- "有没有对爬虫更友好的镜像或静态源"

## 包含的 skill 与工具

| 条目 | 作用 | 何时调用 |
|---|---|---|
| `harvest-surface-expansion` | 单域名 → 全资产面：CT 日志、归档快照、ASN、dork、sitemap/robots、子域、存储桶、影子资产 | 摸清目标到底有几个数据出口 |
| `tools/harvest.py` | 断点续爬主采集器：SQLite 队列、robots 可忽略、sitemap 递归、JS 端点回灌、代理与指纹轮换 | 已确定入口，开始铺量 |
| `tools/jsmine.py` | 前端产物挖掘：接口路径、GraphQL、云密钥、内网地址、sourcemap、遗留调试口 | 拿到 JS 包后第一件事 |

## 与 `02-采集面扩展` 的分工

| 层次 | 去哪 |
|---|---|
| 单站内怎么多拿（sitemap、ID 空间、时间切片、排序切片） | `07-扩量与工具链/02-采集面扩展` |
| 站外还有哪些站 / 哪些历史快照 / 哪些影子入口 | **本子类** |
| 用哪个客户端打通这些入口 | `07-扩量与工具链/01-客户端与指纹工具` |

## 内容速览

- 先"横向"再"纵向"：先确认有几个域、几个子域、几个历史版本，再逐个往下挖。
- 归档源是白捡的历史数据：站点删掉的内容，Wayback 与 CommonCrawl 里还在。
- JS 包是最便宜的端点来源：接口名、appKey、预发域名都在里面。
- 影子资产（预发环境、测试子域、对象存储桶）风控通常比生产弱一个档。

## 使用示例

### 示例 1：只给了一个官网域名
**用户说**：「我只有 www 这个域名，别的入口怎么找。」

**路由**：`harvest-surface-expansion`。

**执行**：CT 日志拉子域 → ASN 反查同段资产 → dork 找 `site:` 与 `inurl:` → 主站 JS 里挖 `api.`/`h5.`/`static.` 域名 → Wayback 拉历史 URL 全集。

**产出**：一张资产表（域名/类型/风控等级/可用入口），按性价比排序。

### 示例 2：抓下来的 JS 包里翻接口
**用户说**：「主站 JS 有 400 KB，怎么看它调了什么接口。」

**路由**：`tools/jsmine.py`。

**执行**：`python3 jsmine.py --dir ./raw --json ./endpoints.json` → 拿到接口路径、GraphQL 端点、云密钥、内网地址 → 回灌采集队列自动扩面。

**产出**：端点清单 + 可直接加入队列的 URL 模板。
