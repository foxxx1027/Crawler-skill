# 反爬分诊与人机对齐

## R — 原文 (Reading)

> 这一章（这本书也是一样）的很多内容都是在介绍如何创建一个更像人而不是更像机器人的网络爬虫。如果你一直被网站封杀却找不到原因，这里有个检查表，可以帮你诊断一下问题出在哪里。
>
> — 瑞安·米切尔，《Python网络爬虫权威指南（第2版）》第14章 14.4，p.194

> 如果Web 表单的一个字段通过CSS 被设置成对用户不可见，那么可以认为普通用户访问网站的时候不能填写这个字段，因为它没有显示在浏览器上。如果这个字段被填写了，就很可能是机器人干的，因此这个提交会失效。
>
> — 瑞安·米切尔，《Python网络爬虫权威指南（第2版）》第14章 14.3.2，p.193

## I — 方法论骨架 (Interpretation)

被封时的默认反应通常是"IP 被拉黑了，换代理"，但作者给的顺序正好相反: 先怀疑自己。

分诊漏斗有固定的层序。第一层是渲染: 页面空白、缺信息、和浏览器里不一样，先问"JS 执行了吗"，而不是先问"是不是被封"。第二层是参数: 提交表单或 POST 前，对照浏览器里真实发出的请求，逐项核对字段名、值、格式。第三层是会话: 已经登录却不保持登录，就查 cookie 是否在每个后续请求里都带上了——登录一次不等于一直登录。第四层是身份: 请求头（尤其 User-Agent，常被忽视的是 Accept-Language）、请求间隔、IP。第五层是交互面: 有没有填人类看不见的隐藏字段、有没有访问 CSS 隐藏的链接。

"像人"不是一句伪装口号，而是四个可以逐项比对的维度: 请求头是否与真实浏览器一致、cookie 是否前后一致、时间上是否快得不正常、交互面是否只碰人类能看见的东西。

蜜罐是这套方法里最硬的一条红线: 人类看不见、程序能读到的东西一律不碰；必须提交的令牌，只回传页面当前值，绝不缓存旧值重复使用。

五层都对齐之后仍然失败，才说明问题在对方的应用层风控；此时的正确动作是改路径（找对方自用的接口、降速）或联系站方，而不是继续加代理。

## A1 — 书中的应用 (Past Application)

### 案例 1: 空白页不等于被封
- **问题**: 抓下来的页面是空白、缺信息，或与浏览器里看到的内容不一致。
- **方法论的使用**: 检查表第一条就把这类现象指向"网站创建页面的 JavaScript 执行有问题"，并要求去看第 11 章判断 JS 到底承担什么职责（p.194）。
- **结论**: 空白页首先是渲染层问题，不是身份层问题。
- **结果**: 把"要不要执行 JS"和"是不是被封"分开处理，避免了无谓地换 IP。

### 案例 2: itsatrap.html 上的隐藏链接与隐藏字段
- **问题**: 页面里有 CSS 隐藏的链接和输入框，程序能读到但人类看不到。
- **方法论的使用**: 用 Selenium 遍历所有 `a` 与 `input`，用 `is_displayed()` 筛出不可见元素，打印"这是陷阱"和"不要修改该字段的值"。
- **结论**: 隐藏链接一旦被访问会触发封 IP，隐藏字段一旦被填就会被判为机器人（p.193）。
- **结果**: 程序输出了 `The link http://pythonscraping.com/dontgohere is a trap`、`Do not change value of phone`、`Do not change value of email`，作者据此定下"忽略隐藏字段很危险，与它们交互也要小心"的规则。

### 案例 3: 登录态必须显式携带
- **问题**: 登录成功后，后续请求仍被当成未登录。
- **方法论的使用**: 查会话层——每个后续请求都要显式带 cookie/session，能用一个 Session 贯穿就不要手工搬运（p.138–139）。
- **结论**: "登录一次"只对当次请求有效，不是账号级状态。
- **结果**: 用持久 Session 贯穿后续请求后，登录态恢复稳定。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 同一台机器抓 A 站正常、抓 B 站一直 403，浏览器却能打开 B 站。
2. 抓下来的页面空白或字段缺失，怀疑"被封了"，准备换代理。
3. 登录成功但翻两页就掉线，或表单提交总是失败。
4. 想在提交前"把字段填全"，不确定哪些字段该填、哪些不该碰。
5. 已经换了 IP 仍然失败，想确认问题到底在哪一层。

### 语言信号 (用户的话里出现这些就应激活)

- "一直 403 / 被封了 / 是不是 IP 被拉黑"
- "抓下来是空白页，浏览器能打开"
- "登录之后又掉线了"
- "表单提交失败 / 参数不对"
- "隐藏字段要不要填 / honeypot / anti-bot / blocked / 像人一点"

### 与相邻 skill 的区分

- 与 `fetch-tier-triage`（Scrapling）的区别: 那个梳理"工具档位与能力边界"；本 skill 是"已经被拦截后按信号分诊到具体一层"。
- 与 `data-path-cost-ladder` 的区别: 那个判断"该走哪条取数路径"；本 skill 是在路径已定、请求已发之后排查失败原因。
- 与 `captcha-cost-routing` 的区别: 那个算人机验证的成本与分路；本 skill 只负责判断"这是不是验证码层的问题"，不进入成本计算。
- 与 `scraping-compliance-layering` 的区别: 那个回答"该不该做"；本 skill 回答"为什么做不通"。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **先做"自己 vs 别人"的对照**
   - 完成标准: 拿到一个同机同 IP 下的正常站点作为对照组，明确回答"IP 是否被全局拉黑"。
   - 判停条件: 若对照组正常，禁止建议换 IP，直接进入步骤 2。

2. **渲染层**
   - 完成标准: 判断 JS 是否执行（对比 View Source 与渲染后 DOM，或临时禁用 JS 再取一次），给出"是/否"结论。
   - 判停条件: 若确认是静态 HTML 却仍取不到，跳到步骤 3。

3. **参数层**
   - 完成标准: 用浏览器开发者工具抓一次真实请求，逐项比对 method、URL、headers、body 的 name/value，列出差异表。

4. **会话层**
   - 完成标准: 确认每个后续请求都携带 cookie/session，并验证登录态在第二步请求后仍然有效。
   - 判停条件: 若 401/302 到登录页，先修会话，不要与字段缺失混为一谈。

5. **身份层与交互层**
   - 完成标准: 四个维度（请求头、cookie 一致性、请求间隔、交互面）逐项打勾；隐藏字段/隐藏链接一律标记为"不碰"，必须提交的令牌只回传页面当前值。

6. **收口**
   - 完成标准: 若五层全部对齐仍失败，明确写出"问题在对方应用层风控（JS challenge / 指纹 / 账号级限制）"，并给出"改取数路径、降速、联系站方"三条出路之一。
   - 判停条件: 若下一步需要伪造指纹、绕过挑战或破解验证码，停止并转 `scraping-compliance-layering` 判定是否越线。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 还没确认页面是否需要执行 JS: 先用 `data-path-cost-ladder` 判断路径，否则会在渲染层空转。
- 目标需要登录、绕过验证码或挑战才能访问，而你并无授权: 这不是诊断问题，转 `scraping-compliance-layering`。
- 只是想提高抓取速度: 转 `crawl-pacing-and-concurrency`，本 skill 不负责配额设计。

### 作者在书中警告的失败模式

- 403 就归因为"IP 被封"并直接换代理: 作者要求先把渲染/参数/cookie/隐藏字段四层排完（p.194–195）。
- 批量填隐藏字段"求全": 填了人类看不见的字段，反而会被判定为机器人（p.192–193）。
- 把"伪装"当成目标: 作者的表述是"更像人"的一组工程参数，并声明只在有正当理由时使用（p.186–187）。

### 作者的盲点 / 时代局限

- 本书成书于 2017–2018，默认 PhantomJS（已于 2018 年 3 月停止维护），也未讨论 webdriver 指纹识别；今天应改用 Playwright/Puppeteer/CDP，并假设无头会被识别。
- 反爬手段只到 User-Agent / cookie / 限速 / 换 IP 这一层。2019 年以后的主流风控在指纹层（TLS/JA3、canvas/WebGL、字体）、挑战层（Cloudflare/Akamai JS challenge、PoW）、行为层（滑块/点选/短信）与协议层（签名、响应加密）。本书的"四维对齐"是必要但不充分的下限。
- "联系 webmaster 请求许可"仍有效，但现代平台多走工单/法务通道；书中把它当成个人对个人的沟通，低估了组织流程。
- "90%/99% 的机器人能被简单技术挡住"是经验修辞，书中无样本、无测量，不应作为基线引用。

### 合规红线

- 本 skill 只做诊断与"与自己对照"，不提供规避访问控制的具体手段（不教伪造指纹、不教绕过 JS challenge、不教破解验证码）。
- 适用范围仅限自有系统、已授权目标或公开测试环境；遇到需要绕过技术措施才能通过的情形，输出只能是"停手/走官方渠道"。

### 容易混淆的邻近方法论

- "伪装成浏览器"与"与真实浏览器对齐": 前者是目的论口号，后者是可逐项核对的四维清单。
- "换 IP"是四层之后的最后手段，不是第一响应。
