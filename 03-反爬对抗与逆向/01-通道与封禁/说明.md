# 01 通道与封禁（已改为「被拦就换身份」）

## 解决什么

不再花时间判断"是哪一层拦的"，改成**按成本顺序逐个换身份，换到通为止**。五层分诊保留，但降级为"换了一轮都不行时的排查表"，不是前置门槛。

| 现象 | 优先动作（不是排查，是直接换） |
|---|---|
| 403 / 429 | 换 TLS 指纹（curl_cffi impersonate）→ 换 IP → 换渲染内核 |
| 空白页 / 只有骨架 HTML | 换浏览器内核（camoufox / patchright）→ 抓 XHR |
| 登录掉线 / cookie 秒失效 | 会话池 + 指纹与 UA 同源绑定 |
| 一 attach 就退出 / 控制台无限断点 | 关 devtools 检测信号，或直接不用浏览器（回退接口） |
| 抓包零请求 / 只有 Wireshark 能看到 | 证书锁定 / 双向认证 / QUIC → 换证书锁定专用手段，或直接逆向 so 层 |

## 包含的 skill（口径已改）

| skill | 新口径 | 何时调用 |
|---|---|---|
| `capture-failure-triage` | 保留通道分类，但结论从"记录抓不到"改成"这条通道改用哪种注入方式"：QUIC → 关 QUIC 降级 HTTP/2；证书锁定 → Frida hook SSL 校验或改 so；双向认证 → 提取客户端证书 | 抓包只有 Wireshark 有流量 |
| `anti-bot-triage-and-human-parity` | 五层不再按"低侵入优先"，改成**按性价比排序**：TLS 指纹（0 成本）→ header 全套（0 成本）→ cookie 同源（低）→ IP 段（中）→ 浏览器内核（高）。默认从第一步直接打，不打完五层不停 | 403 / 被封 / 想直接换 IP |
| `anti-debug-triage` | 从"逐个信号低侵入处理"改成"**信号全关 + 反检测内核**"：patchright 关掉 `Runtime.enable` 泄漏、nodriver 走真实 CDP、camoufox 内置反指纹 | 自动化被识别 / 控制台被禁 |

## 换身份的四件套（按性价比排序，逐级叠加）

### 1. TLS / HTTP2 指纹（成本 0，收益最大）

```python
# curl_cffi：TLS ClientHello + HTTP/2 指纹整体伪装成真实浏览器
from curl_cffi import requests as creq

r = creq.get(
    "https://<PH:target>/api/list?page=1",
    impersonate="chrome124",          # 也支持 safari17_0 / firefox133 / edge101
    headers={"Accept-Language": "zh-CN,zh;q=0.9"},
    proxies={"https": "http://<PH:proxy>"},
    timeout=20,
)
```

```python
# httpx 走 curl_cffi transport，保留 httpx 的异步与连接池
import httpx
from httpx_curl_cffi import CurlCffiTransport

client = httpx.AsyncClient(transport=CurlCffiTransport(impersonate="chrome124"))
```

绝大多数"requests 403、浏览器 200"的站，这一层就能解决——对方在比对 JA3/JA4 与 header 顺序，跟 UA 无关。

### 2. header 全套与顺序

```python
HEADERS = {
    "sec-ch-ua": '"Chromium";v="124", "Google Chrome";v="124", "Not-A.Brand";v="99"',
    "sec-ch-ua-mobile": "?0",
    "sec-ch-ua-platform": '"Windows"',
    "sec-fetch-dest": "empty",
    "sec-fetch-mode": "cors",
    "sec-fetch-site": "same-origin",
    "accept": "application/json, text/plain, */*",
    "accept-language": "zh-CN,zh;q=0.9",
    "accept-encoding": "gzip, deflate, br, zstd",
    "origin": "https://<PH:target>",
    "referer": "https://<PH:target>/",
}
```

顺序要跟真实浏览器一致（`sec-ch-ua` → `sec-fetch-*` → `accept` → `referer`）；`accept-encoding` 里加 `br, zstd` 但客户端不支持解压会直接炸——用 curl_cffi 时它是支持的。

### 3. IP 段（成本中）

| 类型 | 适用 | 备注 |
|---|---|---|
| 住宅代理 | 强风控站、需要长期会话 | 按 GB 计费，别拿它下大文件 |
| 4G/5G 拨号池 | 社交/电商/票务 | 换一次 IP 成本最低，重拨即换 |
| 机房代理 | 弱风控站、大流量 | 便宜、容易被整段封 |
| 移动端蜂窝（真机池） | APP 接口 | 与设备指纹一起才有意义 |

轮换策略：**按域名分摊出口 + 单 IP 熔断**（实现见 `06-02-速率与范围`），不要全站共用一个池。

### 4. 浏览器内核（成本高，最后用）

```python
# camoufox：Firefox 内核 + 内置反指纹，能直接扛 Cloudflare 托管挑战
from camoufox.sync_api import Camoufox

with Camoufox(headless=True, humanize=True, geoip=True, locale="zh-CN") as page:
    page.goto("https://<PH:target>/list")
    page.wait_for_selector(".item")
```

```python
# patchright：playwright 补丁分支，关掉 Runtime.enable / Console.enable 的 CDP 泄漏
from patchright.sync_api import sync_playwright

with sync_playwright() as p:
    ctx = p.chromium.launch_persistent_context(
        user_data_dir="./profile",
        channel="chrome",
        no_viewport=True,
        args=["--disable-blink-features=AutomationControlled"],
    )
    page = ctx.new_page()
    page.goto("https://<PH:target>/list")
```

```python
# nodriver：undetected-chromedriver 作者的新作，直接走 CDP，不产生 webdriver 特征
import nodriver as uc

async def main():
    browser = await uc.start(headless=True)
    page = await browser.get("https://<PH:target>/list")
    await page.sleep(5)

uc.loop().run_until_complete(main())
```

三者选择：Cloudflare 托管挑战 → camoufox；Cloudflare 普通 + Turnstile → patchright + 打码；DataDome / PerimeterX → 住宅 IP + camoufox + 低频。

## 被封的自动降级链（写进中间件，不要人工介入）

```
第 1 次 403 → 换 impersonate 目标（chrome124 → safari17_0 → firefox133）
第 2 次 403 → 换 IP，保留 cookie
第 3 次 403 → 换 IP + 换 cookie 池
第 4 次 403 → 降 HTTP/2 为 HTTP/1.1 再试（部分 WAF 只查 h2 指纹）
第 5 次 403 → 该 URL 交给浏览器内核队列（camoufox）
仍失败      → 记入 dead 队列，换数据源（镜像站 / Wayback / APP 接口）
```

## 不该在这里解决

- 包已抓全，只是参数被加密 —— 转 `03-Web参数定位`。
- 验证码过不去 —— 转 `02-人机验证`。
- 想要更高的吞吐与更大的采集面 —— 转 `06-02-速率与范围` 与 `07-扩量与工具链`。

## 内容速览

- 403 的第一嫌疑人永远是 **TLS 指纹**，不是 IP：先 `impersonate`，再谈代理。
- "像人"的最低配版本是 TLS + header 顺序 + cookie 同源；UA 单独改等于自曝。
- 浏览器内核是**昂贵手段**，能用接口解决就别开浏览器；开了就别计较内存。
- 通道问题（证书锁定 / 双向认证 / QUIC）在应用层无解，只能在传输层或 so 层动手。

## 使用示例

### 示例 1：requests 403，浏览器正常
**用户说**：「同一个 URL，浏览器能开，requests 就 403，帮我换 IP。」

**路由**：`anti-bot-triage-and-human-parity` —— 先别买代理。

**执行**：
1. `curl_cffi` + `impersonate="chrome124"` 重放 → 大概率直接 200。对方在查 JA3。
2. 若仍 403，补齐 `sec-ch-ua` / `sec-fetch-*` 全套并按浏览器顺序排列。
3. 若仍 403，才上代理换 IP 段。
4. 全程把成功的那组参数固化进 `DEFAULT_REQUEST_HEADERS`。

**产出**：一组可复用的"身份包"（TLS 目标 + header 全序 + cookie 来源），成功率 ≥ 95% 再谈扩量。

### 示例 2：抓包零请求
**用户说**：「App 能正常用，代理和证书也装好了，但抓包工具里一条请求都没有。」

**路由**：`capture-failure-triage`。

**执行**：
1. Wireshark 对照：有 UDP 443 → QUIC，关掉 QUIC 或强制 TCP。
2. 握手就断 → 证书锁定：Frida hook `SSL_CTX_set_verify` / `X509TrustManager`，或直接改 so 里的校验分支。
3. 要求客户端证书 → 从 APK 里提 `.p12/.bks` 导入抓包工具。
4. 只有零星流量 → 长连接/推送，改抓 WebSocket 帧。

**产出**：一条可用通道（QUIC 关闭 / 证书校验 hook / 客户端证书导入）+ 后续采集用该通道重放。
