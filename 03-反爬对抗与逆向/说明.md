# 03 反爬对抗与逆向

## 这一类管什么

取数通道建立之后遇到的**阻力**：包抓不到、请求被拦、有验证码、参数加密、App 加固。它的第一动作永远不是"上工具"，而是**分诊**——先判断阻力落在哪一层，再选成本最低的手段。

## 什么时候进这里

- 浏览器能打开，脚本拿不到 / 拿到空页 / 403。
- 代理和证书都装了，抓包工具里一条请求都没有。
- 参数是密文，前端搜不到生成处。
- 目标是 App，怀疑加固或 native 加密。

## 什么时候不该进来

- 还没确认要不要抓、值不值得 —— 回 `01-决策与准入`。
- 免费入口还没试完 —— 回 `01-决策与准入/02-成本与路径`。
- 已经定位到生成函数，只是要验"复现值对不对" —— 留在本类 `03-Web参数定位` 的 `sign-reproduce-acceptance`，不要进 `04-JS混淆还原`。

## 子类

### `01-通道与封禁`
先解决"看不到/发不出"，再谈加密。抓不到包、被封、调试被识别，三个不同现象。
包含 `capture-failure-triage`、`anti-bot-triage-and-human-parity`、`anti-debug-triage`。

### `02-人机验证`
验证码出现时决定：自动化过、人工过一次、接打码平台、协议还原，还是降频/换端。
包含 `captcha-cost-routing`。

### `03-Web参数定位`
Web 端加密参数从"值从哪来"到"生成链"到"复现值对不对"的完整链路，含补环境。
包含 `js-param-locate-ladder`、`ast-restore-locate-and-protocol`、`js-env-patch-loop`、`sign-reproduce-acceptance`。

### `04-移动端逆向`
App 上的同类问题：先判有没有壳，再在 Java 层找，落到 native 层再用 hook / Unidbg。
包含 `android-param-locate`、`android-unpack-gate`、`native-hook-or-unidbg`。

## 类内推荐顺序（重要）

```
现象分诊（01）→ 验证码成本（02，若有）→ Web 定位（03）→ 代码不可读时转 04-JS混淆还原 → 回来做复现验收
移动端则：判壳（04 的 android-unpack-gate）→ Java 层定位 → native 层
```

顺序颠倒的代价：先逆 JS 再发现是会话问题，或者先脱壳再发现有壳但不是关键路径。

## 常见走错路径

- 抓不到包就去改请求头 —— 通道问题不在应用层。
- 被封就换 IP —— 先按五层分诊，很多封禁是会话或参数问题。
- 搜不到 sign 就扩大关键词 —— 应该换定位手段（调用栈、事件断点、内存漫游）。
- 把"补完环境不报错"当成成功 —— 判据是产物与服务端一致。

## 合规红线

本类所有 skill 的边界段都写明：仅限自有系统、已授权目标或公开测试环境；不提供针对未授权目标的攻击配方。
