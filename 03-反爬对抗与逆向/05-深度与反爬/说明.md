# 05 深度与反爬

## 解决什么

能抓到首页、能抓到几十条，但**再往下就没了**：无限滚动加载不出来、分页到第 10 页断、403/429 反复、Cloudflare 转圈、只拿到骨架。这一层处理"怎么把深度和覆盖面推上去"。

## 触发信号（用户原话）

- "只抓到首页 / 只抓到几十条"
- "翻到第 10 页就返回空"
- "无限滚动抓不到后面的"
- "403 / 429 / 一直转圈 checking your browser"
- "sitemap 里没东西，怎么找全量 URL"

## 包含的 skill

| skill | 作用 | 何时调用 |
|---|---|---|
| `crawl-depth-and-antibot` | 反爬四层判层（网络/指纹/行为/内容）→ 递归吃 sitemap → JS bundle 挖隐藏 API 与 GraphQL → 分页与游标穷举 → 无头渲染 → 代理池与 UA/TLS 轮换 → WAF 指纹识别 | 抓不深、抓不全、被拦 |

## 本子类与相邻子类的分工

| 现象 | 去哪 |
|---|---|
| 完全看不到流量（证书锁定/QUIC） | `01-通道与封禁` |
| 看到了但被拒（403/空白） | `01-通道与封禁` 先换身份 |
| 有验证码 / 滑块 | `02-人机验证` |
| 参数被加密、要签名 | `08-请求层逆向与签名` |
| **深度不够、量不够、WAF 拦** | **本子类** |

## 内容速览

- 判层优先于技巧：先确定是"没请求到"、"请求被拒"、还是"请求通了但内容不在 HTML 里"，三种修法完全不同。
- sitemap 是第一优先：很多站的 sitemap 直接给出全量 URL，绕过所有分页限制。
- JS bundle 里挖端点比逆向签名便宜一个数量级——先挖，挖不到再逆。
- 代理池决定"能跑多久"，指纹决定"能不能跑"，两件事都要，但顺序是先指纹后代理。

## 使用示例

### 示例 1：翻到第 10 页就空
**用户说**：「列表页 page=10 之后全空，但站里明显几十万条。」

**路由**：`crawl-depth-and-antibot`。

**执行**：① 试 `offset` / `cursor` / `since_id` 三种游标，看哪种能翻穿；② 跑 sitemap 递归拿全量 URL；③ 都失败则用时间/价格/分类维度切片，把"一次取 1000 条上限"拆成 N 个窗口。

**产出**：可翻穿的分页方案 + 全量 URL 清单 + 每个切片的条数对账。

### 示例 2：Cloudflare 一直转圈
**用户说**：「用 requests 一直 checking your browser，换 IP 也没用。」

**路由**：本子类（判层）→ `07-扩量与工具链/01-客户端与指纹工具`。

**执行**：先判层——换 `curl_cffi impersonate` 看是否 TLS 指纹问题；仍转圈说明是 JS 挑战，换 camoufox 真浏览器过挑战，再从浏览器里抓出真实 XHR 回放到 HTTP 层。

**产出**：通过的挑战方式 + 从浏览器捞出可重放的接口集合。
