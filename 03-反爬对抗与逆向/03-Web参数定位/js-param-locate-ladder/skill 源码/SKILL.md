# Web 加密参数定位阶梯

## R — 原文 (Reading)

> 另外关于搜索也是有一定技巧的，如果加密参数的关键词是signature，可以直接全局搜索signature，搜索不到可以尝试搜索sign 或者搜索接口名。如果还没有找到位置，则可以使用下面几种方法。
>
> — 李玺, 第3章 3.3.1「巧用搜索」, PAGE 52

---

## I — 方法论骨架 (Interpretation)

这套阶梯的本质不是"八种方法挨个试"，而是"手里有什么信息，就只能用哪一种方法"。信息类型与手段是配对的，配错就白花时间。

有参数名（sign、nonce、x-vt-anti-abuse-header）→ 直接全局搜索，一次命中往往就结束了，连断点都不需要。

搜索失败时只允许小幅换词：签名 → sign → 接口名，两轮为止。继续把关键词越换越宽是无用功，因为打包或混淆后字符串常被抽进数组，命中率随关键词变宽而下降。

有接口、没有名字 → 打开 Initiator 的调用栈（Call Stack），顺着栈往下点到业务函数，生成逻辑通常挂在业务层而不是发送层。

只有触发动作（比如点了"详情"才生成加密后的链接）→ 在 DOM 事件监听上断点。这类加密发生在点击时而不是请求时，所以搜索和堆栈都会落空。

只有一个具体值、连参数名都不知道 → 用值反查代码（内存漫游），把"值→变量→代码位置"建成索引。

每级失败就换级，不在同一级叠加变体。阶梯与载体无关：小程序、App 里同一套逻辑换成"搜关键词 → 追调用栈"仍然成立。

## A1 — 书中的应用 (Past Application)

### 案例 1：VirusTotal——有名字，搜一次就收工（案例已过期，仅演示流程）
- **问题**: 请求头里有个 `x-vt-anti-abuse-header`，不知道该从哪下手。
- **方法论的使用**: 参数名可见，直接 `Ctrl+F` 全局搜索。
- **结论**: 一次命中，定位到 `computeAntiAbuseHeader`，不需要断点，也不需要堆栈。
- **结果**: 复制到控制台直接能跑，随后用 Python execjs 复写（第3章 3.6.1，PAGE 71）。

### 案例 2：朝夕网登录——名字搜不到，转堆栈（案例已过期，仅演示流程）
- **问题**: 表单里有个 32 位的 `txtpassword`，全局搜参数名零命中。
- **方法论的使用**: 换级到 Initiator 堆栈，先在第一层 send 断点，没找到相关方法；再按 Call Stack 往下点，点到 `CheckForm` 才看到 `hex_md5`。
- **结论**: 生成逻辑不在发送层，而在表单校验层——这正是"名字搜不到就查栈"要覆盖的形态。
- **结果**: 确认是 MD5，用在线工具与抓包值比对一致后转 Python 复写（第3章 3.6.3，PAGE 75–76）。

### 案例 3：天津公共资源交易网——搜索和堆栈都失败，转事件断点（案例已过期，仅演示流程）
- **问题**: 列表页 URL 在访问详情页时被加密，静态搜索没有找到生成逻辑，Initiator 堆栈也没有。
- **方法论的使用**: 判定"加密是在点击之后触发的"，改在 DOM 事件监听上断点：选中 a 标签 → 找 event listeners 里的 focus 事件 → 断点 → 按 F11 进入 VM。
- **结论**: 加密发生在点击时，所以前两级必然空手；这不是"搜得不够努力"。
- **结果**: 在 VM 里拿到 AES（ECB/Pkcs7）加密代码（第3章 3.6.6，PAGE 80–81）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 目标前端被 webpack 打成一个大文件，变量名全是单字母，怎么搜都搜不到。
2. 全局搜 `sign` 命中几百处，多数是第三方库，不知道该看哪一个。
3. 参数只在点击、滚动、切 tab 之后才出现，请求时断点里看不到。
4. 手上只有一个固定长度的密文值，参数名都不知道。
5. 断点打不上，或者打了不断——先要判断是定位错了还是被反调试了。

### 语言信号 (用户的话里出现这些就应激活)

- "搜不到 / 全局搜索没结果 / search returns nothing"
- "webpack 打包 / minified / 混淆 / 变量名都是 a b c"
- "Initiator / call stack / 调用栈 / 从哪进来的"
- "断点打不上 / breakpoint never hits / 调试不了"
- "只知道这个值 / only have the value / 32 位密文"

### 与相邻 skill 的区分

- 与 `sign-reproduce-acceptance` 的区别: 后者在"函数已经找到"之后判定复现是否正确；本 skill 只管"把那一行找出来"。
- 与 `anti-debug-triage` 的区别: 本 skill 假设断点能生效；若断点被无限 debugger/控制台检测干扰，那是后者的问题。
- 与 `reverse-cost-ladder` 的区别: 后者回答"要不要花这个成本去逆"；本 skill 回答"下一步该试哪种定位手段"。

## E — 可执行步骤 (Execution)

1. **先写清"我手上有什么"**
   - 完成标准: 归入四类之一——参数名 / 接口地址 / 一个触发动作 / 一个具体值。

2. **按对应级别执行，同一级只做一次**
   - 完成标准: 拿到生成函数，或明确记录"零命中/命中过多"。
   - 判停条件: 参数名命中 → 跳到步骤 4。

3. **记录失败事实并换级，不扩关键词**
   - 完成标准: 写下一行"第 N 级失败 + 观察到的事实"（如"搜 sign 命中 300 处，均在第三方库"），然后进入下一级。
   - 判停条件: 连续两级失败，且参数只在交互后出现 → 直接跳事件监听，不要再搜。

4. **在命中处断点，确认"入口值→出口值"**
   - 完成标准: 能看到函数的输入与输出，并复制出一段可在控制台直接执行的代码。

5. **整理交接物**
   - 完成标准: 产出"生成函数 + 输入参数清单 + 一个真实样本值（明文与密文）"，交给验收协议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 包还没抓到、接口列表都不全——先解决通道，再谈定位。
- 参数其实是明文，只是做了 base64/URL 编码——先肉眼比对一次，别急着上断点。
- 需要决定"这套逆向值不值得做"——那是成本决策，不是定位。
- 目标前端用 wasm/瑞数类动态混淆，字符串检索整条阶梯失效时，要先换策略而不是继续换关键词。

### 作者在书中警告的失败模式

- 搜索失败后无限扩关键词：作者给的是"签名→sign→接口名，然后换方法"，不是继续穷举（PAGE 52）。
- 只看发送层：生成逻辑常在业务层（表单校验、点击回调），栈要往下点（PAGE 75、PAGE 81）。
- "逆向工作本身就很看运气"（PAGE 58）——这句宿命论不能替代换级规则；运气差的信号就是"同一级反复试"。

### 作者的盲点 / 时代局限

- 全书未涉及 WebAssembly/Rust 编译加密、瑞数类动态混淆（BOOK_OVERVIEW 批判段）；这些目标上"搜字符串"从第一级起就不可用，阶梯需要新增"看网络层/内存层"的分支。
- 未系统介绍 sourcemap 这一更便宜的一级：能拿到 sourcemap 时可直接读未混淆源码，比断点省一个数量级。
- 案例与站点强绑定（VirusTotal、朝夕网、新榜、天津公共资源），接口与变量名多已迭代，只能当流程演示。

### 容易混淆的邻近方法论

- `anti-debug-triage`——"调不动"的另一种归因。
- `reverse-cost-ladder`——"该不该逆"的决策，与本 skill 的"怎么找到"不同层。

### 合规红线

仅限自有系统、已授权目标或公开测试环境；不提供针对未授权目标的攻击配方。
