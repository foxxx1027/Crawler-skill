# 03 Web 参数定位

## 解决什么

Web 端"这个参数怎么来的"全链路：**值从哪来 → 值要不要逆 → 用哪种手段定位 → 生成链上溯 → 复现值对不对**，以及把找到的代码搬到 Node 跑时缺环境怎么办。

## 触发信号（用户原话）

- "sign / token 在哪生成 / 搜不到"
- "全局搜 data 命中几百条"
- "刷新就变 / 换验证码不变"
- "补环境 / window is not defined"
- "sign 对不上 / 签名校验失败 / 哪些字段参与签名"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `ast-restore-locate-and-protocol` | 前置一道"值来源判定"：响应体里有=服务器下发（复现上游请求），全量抓包零命中才判 JS 生成；再看生命周期（刷新变/业务动作变） | 反爬虫AST | 手里有个值，不知道该复现请求还是逆 JS |
| `js-param-locate-ladder` | 按"手上有什么信息"选手段：有参数名就搜、有接口查调用栈、只有触发动作就下事件断点、只有值就跑内存漫游；搜不到立刻换级 | 逆向进阶实战 | 已确认要逆 JS，找生成代码 |
| `js-env-patch-loop` | 报错驱动逐个补 window/document/navigator；用 toStringTag 伪装类型；补不动升级 JSDOM/真浏览器；判据是产物与服务端一致 | 逆向进阶实战 | 把原站 JS 搬到 Node 跑 |
| `sign-reproduce-acceptance` | 先用"只改一个参数看服务端是否报签名失败"反证字段集合，再逐字符比对；不一致按字段集合/运行时值/接口绑定三分法排查 | 逆向进阶实战 | 函数已找到，验复现对不对 |

## 类内推荐顺序（严格）

```
值来源判定 → 定位手段 → 生成链 → （代码不可读则转 04-JS混淆还原）→ 补环境 → 复现验收
```

1. `ast-restore-locate-and-protocol`：先决定这个值**要不要**逆。判错方向的代价最大（给服务器给的值逆算法 = 凭空造函数）。
2. `js-param-locate-ladder`：确认要逆之后，按信息类型选手段，单级失败立即换级。
3. 代码不可读 → 转 `04-JS混淆还原`（判层 → 单点还原 → 总装验收）。
4. `js-env-patch-loop`：搬进 Node 后补齐运行环境。
5. `sign-reproduce-acceptance`：最后验值，不要跳过。

## 不该在这里解决

- 包还没抓到 / 通道不通 —— 转 `01-通道与封禁`。
- 只问"该用哪个断点" —— 那是 `js-param-locate-ladder` 的细节，不要从 `ast-restore-locate-and-protocol` 进。
- 整份代码还没还原完就想验值 —— 先转 `04-JS混淆还原/01-判层与总装`。
- 难点在 so/native 层 —— 转 `04-移动端逆向`。

## 内容速览

- 两类错误的代价极不对称：逆了服务器给的值 = 白干；没逆 JS 生成的值 = 继续白干。
- 生命周期对照（刷新页面 vs 换验证码）决定要复现哪一段，比任何断点技巧都关键。
- 补环境"不报错"不等于"像"；唯一判据是服务端接受。
- 签名验收的第一步是**反证字段集合**，不是逐字符 diff。

## 使用示例

### 示例 1：sign 全局搜出 300 处
**用户说**：「POST 里有个 sign，全局搜 sign 命中 300 处，不知道从哪下手。」

**路由**：先 `ast-restore-locate-and-protocol` 判值来源，再 `js-param-locate-ladder` 定位。

**执行**：
1. 拿 sign 的具体值去全部抓包里搜：零命中 → 判 JS 生成（若在响应体出现过，则改为复现上游请求，流程到此结束）。
2. 判生命周期：刷新页面变、换账号不变 → 会话级随机，必须实时算。
3. 定位：搜 sign 命中过多 → 立刻换级，改看该请求的 Initiator 调用栈，从发送函数往上溯。
4. 代码不可读 → 转 `04-JS混淆还原`；搬进 Node 报 `window is not defined` → `js-env-patch-loop`。
5. 复现验收：只改一个参数（如时间戳）看服务端是否报签名失败，先反证字段集合，再逐字符比对。

**产出**：生成函数 + 参与签名的字段清单 + 一个真实明文/密文样本对。

### 示例 2：值只在响应里出现过
**用户说**：「这个 token 在所有抓包里都搜不到，只有某个接口的响应里出现过一次。」

**路由**：不进入本子类的主流程 —— 属"服务器下发"，应转 `02-取数与请求/01-单请求复现` 复现产生它的上游请求，不要逆 JS。
