# 小样本评估协议：固定协议重复测、逐类看 support、极值当异常

## R — 原文 (Reading)

> "为了更精确地估计错分率，需要重复运行多次，然后求平均值，运行100次，获得的平均错分率为3.5%。"
>
> — 郑秋生、夏敏捷, 第18章 PAGE 371–372

---

## I — 方法论骨架 (Interpretation)

1. 先写清分母：样本总量、类别定义、标注条数、留出条数。分母不写，"准确率"无法被任何人复核。
2. 固定协议再跑：划分规则、随机种子、重复次数写进配置。协议一换，前后两次数字就不可比。
3. 小样本不报单次结果：同一协议重复多次（书中为 100 次），报均值与波动，而不是某一次 0.0 或 0.1。
4. 逐类看 support 与 f1：整体 accuracy 会把类别不均衡藏起来；某类没有测试样本时，它的 0.00 是"无样本可评"，不是"模型很差"。
5. 极值当异常：指标落到 0 或 1，先查训练/测试同源、泄漏、样本量远小于特征维度，再谈"改进成功"。
6. 训练集分数与测试集分数并排报：两者都接近 1 先怀疑泄漏；只有测试分数高而训练分数低，也不正常。
7. 验证集不等于测试集：验证集用于调参/早停，测试集应到最后只用一次；把 `validation_data` 当测试集，得到的分数是"被看过的集合上的成绩"。
8. 比较要成对：A 与 B 必须在同一划分协议、同一重复次数下比较；改特征后用同一协议复测，才允许说"更好"。
9. 报告写成固定形态："N 条标注，M 条留出，重复 K 次，accuracy x±y，某类 support n、f1 m"。采集侧同一纪律：不报"共抓 N 条"，按桶报（命中/漏抓/错抓/重复）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 50 封垃圾邮件的重复评估
- **问题**: 50 封邮件里随机抽 10 封做测试，单次错分率在 0.0 与 0.1 之间跳，无法判断"到底是多少"。
- **方法论的使用**: 明确 40 训练 / 10 测试，固定同一随机留出协议重复运行 100 次，取平均值 3.5%（PAGE 371–372）；换成词袋特征后，用同一协议再测一次，才作比较（PAGE 372）。
- **结论**: 单次结果是抽样个案，重复均值才是可报告的估计；换特征必须在同一协议下复测。
- **结果**: 词集版 3.5%（100 次平均），词袋版 100 次平均为 0；作者判为"确实提高准确度"，但 50 条样本上的 0% 更可能是过拟合/同源（PAGE 372，ce05-b）。

### 案例 2: 6 条留言 8:2 划分，support=0 照印
- **问题**: 用 sklearn 在 6 条留言上做 8:2 划分，打印逐类报告。
- **方法论的使用**: `classification_report` 输出"正常言论 0.00 / 0.00 / 0.00 / 0（support=0）"；按规则应先读 support，再读指标（PAGE 377–378，ce04-b）。
- **结论**: 测试集只有 2 条且都属侮辱类，正常类的三项 0.00 表示"没有样本可评"，不能解释为模型在该类表现差。
- **结果**: 作者原样贴出报告，未加一句"该类无测试样本、指标无意义"；读者容易去改模型而不是补样本（PAGE 378）。

### 案例 3: CNN 把测试集当 validation_data
- **问题**: MNIST 手写数字训练得到 `Test accuracy: 0.959`（PAGE 394），这个分数能否当泛化成绩。
- **方法论的使用**: 查"这个分数在哪个集合上算的"——`fit` 时把 `(x_test, Y_test)` 作为 `validation_data`，边训练边看；最后 `evaluate` 仍用同一份数据（PAGE 394，g16-b）。
- **结论**: 0.959 落在"训练中看过"的集合上，不是独立测试集成绩；要报告泛化，必须另留一份只在最后用一次的数据。
- **结果**: 书中照印 0.959；同一章正文写"最大池化"、代码用 `AveragePooling2D`（PAGE 389–394，ce06-b），说明文档与实现也需交叉核对。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 抓了几百条评论、人工标了 60 条，sklearn 报 accuracy 0.92，准备在报告里写"模型准确率 92%"。
2. 看到别人的报告里有 `precision 0.00 / support 0`，或小数据集上的 100%，要判断这份结论能不能用。
3. 两版特征/两个模型各跑一次，问"哪个更好、能不能说改进了"。
4. 采集收尾要写验收报告，日志只有"共抓 N 条"，需要判断其中有效样本有多少。
5. 小样本上出现 0% 错分率或 0.959 这类高分，想确认是不是泄漏、同源或样本量问题。

### 语言信号 (用户的话里出现这些就应激活)

- "准确率 92%，能直接写进报告吗"
- "support 是 0 是什么意思，是不是模型很差"
- "换了特征从 3.5% 降到 0，是不是改好了"
- "100% 准确率能不能用"
- "这个交叉验证是怎么做的"
- "accuracy 0.92 on 60 samples — can I report it?"
- "precision 0.00 but support is 0"
- "is this real cross-validation or just repeated holdout?"
- "validation accuracy vs test accuracy, which one counts"
- "how many annotated samples are enough"

### 与相邻 skill 的区分

- 与 `pagination-acceptance` 的区别: 后者问"抓到的条数对不对"（偏移是否进 URL、条数是否与页数对账）；本 skill 问"分数背后的分母对不对"。两者是同一纪律的采集端与评估端。
- 与 `crawl-scope-and-halt` 的区别: 后者决定抓多少、在哪停；本 skill 不控制采集范围，只判读样本量与指标。
- 与 `requirements-first-data-model` 的区别: 后者在动手前定字段、主键与表结构；本 skill 在数据已就绪后定评估协议与报告形态，不负责建模 schema。
- 与 `semantic-selector-robustness` 的区别: 后者修"抓空/抓错"的解析问题；本 skill 不修选择器，只处理"已抓到样本后如何评估"。若样本本身漏抓严重，先回采集侧按桶对账。
- 与 `http-request-replication` / `form-hidden-state-and-readback` 的区别: 后两者用"重放一次请求 / 写后回读"验证单次操作是否成功；本 skill 用"重复采样"验证一个分数能否代表总体，验收对象是统计结论而不是请求本身。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写清分母与任务定义**
   - 完成标准: 明确样本总量、类别定义、已标注条数、计划留出条数；一句话能复述"这次评估回答什么问题"。
   - 判停条件: 若标注条数少于类别数×2，先补样本，不要开始调模型。

2. **固定评估协议并落盘**
   - 完成标准: 划分规则、随机种子、重复次数写进配置/脚本常量；同一命令重复运行能得到同一结果。
   - 判停条件: 若已有独立测试集且样本充足（千条以上），按标准流程即可，不必套用重复留出协议。

3. **按协议重复运行，记录均值与波动**
   - 完成标准: 至少重复 K 次（小样本建议对齐书中的 100 次量级），报告 `x±y`，不引用单次结果。
   - 判停条件: 若每次运行结果差异大到无法给出区间（如 0.0 与 0.1 反复跳），先扩大样本或分层划分。

4. **逐类报告 support 与 f1**
   - 完成标准: 每个类别都列出 support；support=0 的类别明确标注"指标作废（无样本）"，不把 0.00 当性能。
   - 判停条件: 若关键类别 support=0 或缺席，回到步骤 1 补该类样本；不要用调参掩盖。

5. **极值排查：0/1 先查泄漏与样本量**
   - 完成标准: 出现 0 或 1 时，能给出训练/测试同源、验证集混用、样本量 vs 特征维度、独立测试集缺失等证据；训练分数与测试分数并排展示。
   - 判停条件: 训练与测试都接近 1 且无独立数据 → 判为可疑，不发布结论。

6. **按固定形态输出报告，并核对采集侧**
   - 完成标准: 报告含「N 条标注，M 条留出，重复 K 次，accuracy x±y，逐类 support/f1」；采集侧按桶报（命中/漏抓/错抓/重复），各桶能解释声明总量。
   - 判停条件: 若声明总量与实际样本量脱钩（如"抓了 10 页"实际只有约 20 条），先回采集侧对账，再谈指标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有独立测试集、样本量足够的正式评测：按标准流程做一次即可，重复留出协议只会增加噪声与解释成本。
- 抓不到、抓空、被封，或因验证码/登录态拿不到样本：这是取数问题，转 `semantic-selector-robustness`、`anti-bot-triage-and-human-parity`、`captcha-cost-routing`、`scrapy-login-route-choice`。
- 只想知道分页有没有推进、条数对不对：转 `pagination-acceptance`；本 skill 不替代条数对账。
- 用户要求把 60 条样本上的 0.92 直接写成"模型准确率 92%"：本 skill 的作用是拒绝并改写报告形态，而不是替用户背书。

### 作者在书中警告的失败模式

- **把 0% 错分率当"改进成功"**（第18章 PAGE 372，ce05-b）：50 封样本、词汇表数百维、无独立第三份数据，0% 更可能是过拟合或同源，不是泛化提升。
- **support=0 的 0.00 原样照印**（第18章 PAGE 378，ce04-b）：测试集只剩 2 条且全属一类，正常类 support 为 0；不解释就把"抽样偶然"误读成"模型缺陷"。
- **把 `validation_data` 当测试集**（第19章 PAGE 394，g16-b）：0.959 是被训练中看过的集合上的成绩。
- **随机划分结果不稳定却未标注**（第18章 PAGE 378，p04-b）：原文自己写了"每次的运行结果不一定相同"，报告却没有固定种子与重复次数。
- **声明量与实际样本量脱钩**（第20章 PAGE 407–408，ce01-b）：正文称"爬取了 10 页，所得数据比较有参考价值"，实际只请求到第 1 页、约 20 条进入词频。

### 作者的盲点 / 时代局限

- 本书是项目制入门教材，每章只写到"能演示"：样本极少（6 条留言、50 封邮件、约 20 条评论），无并发、无限速、无日志（PAGE 120–123、150、407–408）。
- 异常被吞：`try/except: continue` 遍布（PAGE 123、131、142、150），失败条数不被记录；评估时"样本为什么少了"无从追溯。
- 成书环境为 Python 3.5（PAGE 4），`sklearn.cross_validation` 在 0.20 后已移除（PAGE 376），2021 年后照抄会直接在 import 处失败。
- 书中名为"交叉验证"的操作，实际是随机留出重复 100 次，不是标准 K 折（PAGE 371–372，g11-b）；名字与实现不符，照名套用会换掉协议。
- 平台入口失效（微信网页版，PAGE 152–190）虽不直接属于评估，但说明全书"作者机器上能跑"不等于可复现。

### 容易混淆的邻近方法论

- **标准 K 折 / 分层交叉验证 vs 书中的随机留出重复**：前者每折轮换、每样本只测一次；后者每次重新随机抽测试集、同一批样本会被反复抽到。两者都叫"交叉验证"，数字不可混比。
- **验证集 vs 测试集**：验证集参与调参与早停，测试集只在最后用一次；混用会把"被看过"的分数当成泛化成绩。
- **采集对账 vs 评估对账**：`pagination-acceptance` 查"抓了几页、每页多少条"；本 skill 查"标注多少条、留出多少条、每类多少条"。

### 合规红线

仅限自有系统、已授权目标或公开测试环境；不提供针对未授权目标的攻击配方，也不提供绕过访问控制或平台限制的手段。
