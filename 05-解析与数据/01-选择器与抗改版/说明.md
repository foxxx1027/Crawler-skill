# 01 选择器与抗改版

## 解决什么

把 HTML 稳定地变成字段：**第一次写对**（选型 + 语义定位），以及**改版之后还能找回来**（存档 + 相似度重定位 + 用可验算字段验收）。

## 触发信号（用户原话）

- "选择器抓空了 / AttributeError"
- "网站改版后全废了"
- "用正则还是 BeautifulSoup / XPath"
- "类名是哈希的 / 结构老变"

## 包含的 skill

| skill | 作用 | 来源 | 何时调用 |
|---|---|---|---|
| `semantic-selector-robustness` | 正则 / BeautifulSoup / lxml-XPath 的选型，优先语义定位而非位置定位；改版后抓错抓空的修复 | 权威指南 2e | 写或修 HTML 解析器 |
| `adaptive-selector-maintenance` | 闭环：存档元素身份 → 相似度重定位 → 用可验算字段验收 → 不达标回退手工选择器并重建存档 | Scrapling 文档 | 有改版前基线、想给定位上保险 |

## 类内先后

1. 首次编写：`semantic-selector-robustness`。
2. 已上线、担心改版：`adaptive-selector-maintenance`（前提是**有历史存档**，没有存档不能事后开启）。

## 不该在这里解决

- 数据其实在 JS/接口里 —— 转 `02-取数与请求/02-接口与表格`。
- 整站前端重构（类名全哈希、Shadow DOM、多实例组件）—— 自适应重定位不适用，应回到人工选择器。
- 分页/并发等工程问题 —— 转 `05-解析与数据/02-建模与分页` 或 `06-工程化与运行/02-速率与范围`。

## 内容速览

- 语义定位优先：按文本/属性/层级关系找，不按第几个 div 找。
- 自适应重定位必须**用可验算字段验收**（能对得上的值），不能只看"找回来了"。
- 没有改版前存档就没有自适应；这条限制比任何算法都重要。

## 使用示例

### 示例 1：上周还好，今天全是 None
**用户说**：「上周还能抓到，今天标题全变成 None，网站改版了。」

**路由**：`semantic-selector-robustness` 先上；`adaptive-selector-maintenance` 只在**有改版前存档**时才用。

**执行**：
1. 先确认数据还在 HTML 里（如果转成了接口，去 `02-取数与请求/02-接口与表格`，别在这里修选择器）。
2. 用语义定位替代位置定位：按标题文本、稳定属性、层级关系找，不用 `div:nth-child(3)`。
3. 若有历史存档：相似度重定位 → 用**可验算字段**（价格、日期、编号）验收 → 不达标就回退手工选择器并重建存档。

**产出**：修好的选择器 + 一条验收字段（例："用发布日期校验，必须与页面显示一致"）。

### 示例 2：整站重构，类名全哈希
**用户说**：「这个站整站重构，类名全是 `css-1x2y3z` 这种，自适应还能救吗？」

**路由**：`adaptive-selector-maintenance` 明确不适用（整站前端重构、多实例组件、Shadow DOM 都在其边界外）。改走 `semantic-selector-robustness` 的语义定位，必要时人工重建。
