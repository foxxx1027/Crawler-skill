# 02 静态审计

## 解决什么

拿到一个混淆/压缩/剥离过的产物（JS bundle、H5 包、so、剥离二进制），在**不运行**的前提下摸清结构：字符串表、函数边界、调用图、模块依赖、可疑的数据处理链。

## 触发信号

- "400 KB 的压缩 JS，从哪看起"
- "函数名全是 a/b/c，没有意义"
- "剥离了符号的 so，怎么定位关键函数"
- "这个包到底做了几件事"

## 包含的 skill

| skill | 作用 |
|---|---|
| `source-and-binary-static-audit` | 源码审计与剥离二进制审计：输入源追踪、FLIRT/FLAIR 签名、结构体与类层次恢复、IDAPython 批量脚本 |

## 工具口径

- JS：美化（`js-beautify` / `prettier`）→ 字符串表提取 → 可疑 API 检索（`encrypt`、`md5`、`charCodeAt`、`fromCharCode`、`atob`、`eval`、`Function`）→ 调用图。
- 二进制：导入表 → 字符串 → xref → FLIRT 恢复库函数 → 结构体。
- 产物同一份要留哈希与版本号，版本是后续迁移的唯一锚。

## 与相邻子类的分工

| 情况 | 去哪 |
|---|---|
| 只想知道某个值在哪算 | `01-锚点定位` |
| 要追值怎么流动 | `03-数据流与污点` |
| 分支太多算不出来 | `04-约束求解` |
| 有壳/反调试 | `05-脱壳与反调试` |

## 内容速览

- 先看"字符串密度"：字符串集中的区域就是业务逻辑区，加密实现一定在附近。
- 先建立函数清单与调用图，再决定读哪个函数，不要顺着顺序读。
- 记录"特征字符串 → 函数偏移"映射，版本升级后靠这张表迁移。

## 使用示例

**用户说**：「H5 包里的 JS 全被压缩了，怎么找加密入口。」

**执行**：美化 → 提字符串表（URL、header 名、报错文本）→ 检索 `CryptoJS`/`md5`/`sha`/`sign` 相关 API → 用字符串 xref 定位调用点 → 输出"候选加密函数清单 + 各自入参形态"，交给 `01-锚点定位` 精确打击。

**产出**：模块结构图 + 候选函数清单 + 特征字符串表（供下次版本迁移）。
