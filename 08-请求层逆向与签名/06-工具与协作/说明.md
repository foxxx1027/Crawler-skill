# 06 工具与协作

## 解决什么

一次逆向是个人行为，**长期逆向是工程问题**：版本升级、偏移迁移、多人共享 IDB、批量样本、知识沉淀。这一子类解决"怎么让逆向成果不随版本作废"。

## 触发信号

- "它一升级我的脚本全废了"
- "两个人改同一个 IDB 冲突"
- "几百个样本要批量标注"
- "上次那个结论记哪了"

## 包含的 skill

| skill | 作用 |
|---|---|
| `reverse-engineering-tooling-and-collaboration` | IDAPython 插件与批量标注、共享 IDB、命名规范、语义着色、YARA 沉淀、协作流程 |

## 配套做法

| 问题 | 做法 |
|---|---|
| 版本升级偏移变了 | 维护"特征字符串 → 函数"映射表，升级后按特征重定位，不按偏移 |
| 多人协作 | IDB 只读副本 + 脚本化产出（命名/注释写成脚本，重放即可） |
| 批量样本 | 统一命名规范 + 自动标注脚本 + 结果落 JSON |
| 结论沉淀 | 每个目标一份 `findings.md`：锚点、函数、入参、验证样本哈希 |

## 内容速览

- 逆向的主要成本不在第一次，在第 N 次改版。所有工作都要按"可重放"设计。
- 脚本化标注 > 手工标注：手工改的注释下次就没了，脚本每次都能重放。
- YARA 规则是逆向的自然产物：把"这个函数长这样"变成可检索的指纹。

## 使用示例

**用户说**：「前端版本从 0.0.179 升到 0.0.181，我的定位脚本全失效了。」

**执行**：定位脚本里不要写偏移，写特征（函数体里的常量、字符串、调用序列）→ 升级后用特征重新扫描 → 输出新旧偏移对照表 → 人工确认 2 个锚点即可全量迁移。

**产出**：特征定位脚本 + 新旧偏移映射表。
