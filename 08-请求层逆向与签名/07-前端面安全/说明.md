# 07 前端面安全

## 解决什么

签名与校验有一半在**前端**：DOM 执行点、存储面（localStorage/IndexedDB）、跨窗口消息、CSP 与跨域配置、原型污染。这一子类回答"哪些值在前端就能改、改了服务端认不认"。

## 触发信号

- "这个值在控制台能改，改了请求就对了"
- "数据存在 localStorage 里，能不能直接读"
- "前端做了限制，接口是不是也做了"
- "postMessage 没验来源"

## 包含的 skill

| skill | 作用 |
|---|---|
| `client-side-and-frontend-security` | DOM XSS、CSRF、点击劫持、postMessage、CORS/CSP、原型污染、端侧存储审计，画信任边界 |

## 与相邻子类的分工

| 情况 | 去哪 |
|---|---|
| 前端算的签名要还原 | `01-锚点定位` → `03-数据流与污点` |
| 服务端参数校验绕过 | `03-反爬对抗与逆向/03-Web参数定位` |
| 会话与权限 | `02-取数与请求/04-会话与身份` |

## 内容速览

- 前端的"校验"默认不可信，但**前端生成的值**往往就是服务端要的值——所以既要会绕，也要会算。
- 存储面是采集的捷径：`localStorage` 里常有完整对象（比解析 HTML 便宜十倍）。
- 信任边界要画清楚：哪个值由前端产生、哪个值服务端会复核。

## 使用示例

**用户说**：「列表数据好像存在 localStorage 里，还用不用解析页面。」

**执行**：打开 DevTools → Application → Local Storage / IndexedDB 找结构化对象 → 若存在完整 JSON，直接采集存储层（配合 `02-取数与请求/04-会话与身份` 保持会话）→ 输出字段表，跳过 HTML 解析。

**产出**：存储结构说明 + 可直接消费的字段清单。
