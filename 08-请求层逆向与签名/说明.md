# 08 请求层逆向与签名

## 解决什么

请求发得出去、身份也有，但**参数不对**：`sign` 算不出来、`token` 一遍就变、`x-sgext` 看不懂、加密参数一改就报错。这一大类处理"怎么把一个合法请求拆开、还原出生成规则、再自己造一个"。

## 在整条流水线里的位置

```
01 准入 → 02 取数 → 03 反爬 ─┬→ 04 JS 混淆还原 ─┐
                              └→ 08 请求层逆向 ──┴→ 07 扩量 → 05 解析 → 06 工程化
```

03 管"被不被拦"，04 管"代码读不读得懂"，08 管"参数怎么算出来"。三者串行，顺序不能反：读不懂代码就定位不到生成函数。

## 七个子类（按逆向推进顺序）

| 子类 | 一句话 | 典型信号 |
|---|---|---|
| `01-锚点定位` | 用已知字符串/符号直接落到目标函数，不做逐层回溯 | "不知道 sign 在哪算的" |
| `02-静态审计` | 混淆包/二进制的整体结构、字符串表、调用图 | "一坨压缩后的 JS" |
| `03-数据流与污点` | 追一个值从哪来、经过什么变换、到哪去 | "token 传了七八手" |
| `04-约束求解` | 分支里带版本号/时间窗/常量表，反推满足条件的输入 | "算出来总差一位" |
| `05-脱壳与反调试` | App 侧 so 加壳、附加调试器即退出 | "H5 包看不懂 / 有壳" |
| `06-工具与协作` | IDAPython 批量标注、符号迁移、YARA 沉淀、共享 IDB | "版本升级后偏移全变了" |
| `07-前端面安全` | DOM 执行点、存储面、CSP/跨域，前端逻辑与信任边界 | "值在前端就能改" |

## 验收口径（唯一标准）

不是"看起来对"，而是：**同样的输入三元组下，你算的签名与抓到的签名逐字节相同**，再换十组样本回归。做不到这一步，等于没还原。

## 不该在这里解决

- 还没确认是被哪一层拦的 —— 回 `03-反爬对抗与逆向/01-通道与封禁`。
- 代码可读但结构混乱（AST 级还原）—— `04-JS混淆还原`。
- 会话/权限问题 —— `02-取数与请求/04-会话与身份`。

## 内容速览

- 定位优先于通读：99% 的签名函数是靠一个字符串锚点（错误提示、header 名、appKey）直接找到的，不是从头读完。
- 先静态后动态：静态能看清结构，动态才能拿到运行时的真实输入。
- 版本是最大的敌人：把"函数偏移 → 特征字符串"的映射固化成脚本，下次升级十分钟迁移完。
- 还原完成的标准是能生成，不是能读懂。
