# 05 脱壳与反调试

## 解决什么

产物被保护：加了壳、有反调试、IDA 打开错乱、attach 就退出、dump 下来跑不起来。这一子类按"判壳 → 处理反调试 → 找 OEP → dump/修复 → 定位真实入口"的顺序把程序恢复成可分析状态。

## 触发信号

- "一 attach 调试器进程就退出"
- "IDA 反汇编一片空白/错乱"
- "dump 下来跑不起来，IAT 是坏的"
- "App 的 so 加了壳，字符串全是乱码"
- "H5 包能打开但运行时才解密"

## 包含的 skill

| skill | 作用 |
|---|---|
| `anti-debugging-and-unpacking` | 判壳与判保护、反调试处理、找 OEP、dump 与 IAT 修复、定位真实入口 |

## 方法

1. 判壳：区段熵、导入表异常少、入口点在非标准区段、字符串不可读。
2. 判保护：`BeingDebugged`、`NtQueryInformationProcess`、时间差检测、硬件断点检测。
3. 处理反调试：按信号逐个处理，从侵入性最低的开始。
4. 找 OEP：内存断点 / 单步到跳转 / 区段权限变化。
5. dump + 修复 IAT + 重定位。
6. 回到 `02-静态审计` 重新看结构。

## 与相邻子类的分工

| 情况 | 去哪 |
|---|---|
| 没加保护，只是没符号 | `02-静态审计` |
| 脱完壳要定位函数 | `01-锚点定位` |
| 虚拟化壳（VMProtect/Themida 级） | 超出本子类，按"动态采行为"处理 |

## 内容速览

- 先判后动：不清楚保护类型就上工具，只会浪费时间。
- 反调试是逐个信号的对抗，不是一次性全关。
- dump 不修复等于没 dump：IAT 坏的程序任何静态工具都读不出有效调用。

## 使用示例

**用户说**：「so 库拖进 IDA 全是 `db 0x??`，导出的 JNI 函数只有一个。」

**执行**：先判壳（区段熵高、`init_array` 指向解密 stub）→ 动态跑起来后在内存里找解密完成时机（内存断点打在 `.text` 可写变化处）→ dump 内存段 → 修复 section 与重定位 → 回到 IDA，此时能看到真实字符串与 JNI 注册表。

**产出**：可分析的 so + 真实入口列表 + 特征字符串表。
