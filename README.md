# Crawler-Skill

> **一套面向网络数据采集全流程的可执行技能库：60 个方法论技能 × 八大类工作流导航 × 触发式调用机制。**

把网络爬虫领域的成熟作业方法论固化为一个个可独立调用的「技能卡片」——每张卡片回答一个问题：**遇到这类采集场景，该怎么一步步做、依据是什么、什么时候不该这么做。** 适用于人工排障与方案参考，也可直接装载到 AI Agent（Claude Code / Cursor / Trae 等）作为可自动触发的领域技能。

---

## 一、这套技能库是什么

一个技能 = 一份结构化的采集作业方法论，包含**方法论出处、方法论骨架、应用案例、触发场景、可执行步骤、使用边界**六个固定部分。60 个技能不是并列的目录，而是按一条真实的采集流水线组织——从「这个站能不能抓、从哪进最省事」的准入决策，到请求复现、反爬对抗、JS 混淆还原、签名逆向，再到解析建模与工程化运行——覆盖一个采集任务从立项到交付的完整链条。

**规模一览**：

| 维度 | 数量 |
|---|---|
| 技能总数 | 60 |
| 采集工作流大类 | 8 |
| 子类场景目录 | 31 |
| 技能间引用关系（frontmatter 显式声明） | 48 |
| 触发测试用例 | 522 |
| 随库盲测结果文档 | 51 |
| 随库附带采集工具脚本 | 2 |

## 二、总体架构：三层设计

```
Crawler-skill/
│
├── 说明.md                         ← 全局地图：八大类索引 + 按"你现在的处境"反查
├── 流程总纲.md                     ← 端到端 SOP：六段主流程 + 判层决策树 + 验收口径 + 实战样例
│
├── 01-决策与准入/                   ← ① 导航层：按采集工作流组织的八大类（共 31 个子类）
│   ├── 01-合规与尽调/                  每个子类一份说明.md：定位 + 技能清单 + 触发信号
│   │   ├── scrape-preflight-and-entry-ladder/
│   │   │   └── skill 源码/SKILL.md     ← ② 技能层：技能本体
│   │   └── scraping-compliance-layering/
│   └── 02-成本与路径/                  （3 个技能）
├── 02-取数与请求/                   （9 个技能，下分 4 个子类）
├── 03-反爬对抗与逆向/               （12 个技能，下分 5 个子类）
├── 04-JS混淆还原/                   （8 个技能，下分 3 个子类）
├── 05-解析与数据/                   （5 个技能，下分 3 个子类）
├── 06-工程化与运行/                 （12 个技能，下分 4 个子类）
├── 07-扩量与工具链/                 （1 个技能 + 选型/扩面方法论 + 可运行脚本）
│   └── 03-资产面扩张/tools/             harvest.py / jsmine.py
└── 08-请求层逆向与签名/             （8 个技能，下分 7 个子类）
```

- **导航层（八大类目录）**：按采集工作流组织，每层携带一份 `说明.md`——这个子类解决什么问题、触发信号（用户原话）、技能清单与口径；`说明.md` 与 `流程总纲.md` 是按**工作流**找技能的两个入口；
- **技能层（60 个技能目录）**：每个技能一份 `SKILL.md`，是技能的**本体**。技能目录存在两种布局（`<slug>/SKILL.md` 与 `<slug>/skill 源码/SKILL.md`），内容结构完全一致，装载方式见第六节；
- **质量层（随技能目录携带）**：每个技能的 `test-prompts.json` 触发测试用例与 `test-results.md` 盲测结果，构成可验证、可回归的质量证据。

## 三、技能卡片解剖

每个技能是一份固定结构的 `SKILL.md`，由 **frontmatter 元数据 + 六段正文**构成：

### frontmatter（机器读取部分——决定技能何时被自动激活）

```yaml
---
name: scrape-preflight-and-entry-ladder   # 技能唯一标识（=目录名）
description: |                            # 何时调用 + 何时不调用 + 中英双语触发词
  用户问"这个站能不能抓 / 会不会被封"时调用：用五个只读信号
  （robots / Sitemap / 规模 / 技术栈 / 所有者与 ToS）做项目级 go/no-go。
  不适用于：已决定要抓、只想比较取数路径（转 data-path-cost-ladder）。
  Trigger：尽调 / preflight / robots / ToS / go-no-go / legal to scrape。
source_chapter: ……                       # 方法论出处定位（可溯源）
tags: [preflight, compliance, due-diligence, go-no-go]
related_skills:                           # 技能间引用关系（依赖/对比/组合）
  - slug: data-path-cost-ladder
    relation: contrasts-with
---
```

### 六段正文（人与 Agent 共读部分）

| 段 | 名称 | 作用 |
|---|---|---|
| **R** | 原文依据 | 方法论的一手出处引用（章节可溯），保证「有据可查」 |
| **I** | 方法论骨架 | 用结构化语言重写的核心逻辑与关键判据，不读原文也能懂 |
| **A1** | 应用案例 | 1–3 个该方法论被实际使用的案例：遇到什么问题 → 怎么用 → 得出什么 → 结果如何 |
| **A2** | 触发场景 ★ | 用户会在什么情境下需要它（3–5 条）、语言信号（中英双语）、与近缘技能的区分——这是技能被精准调用的关键 |
| **E** | 可执行步骤 | 3–7 步操作流程，每步带**完成标准**与**判停条件**，拿来即用而非空泛原则 |
| **B** | 边界 ★ | 什么时候**不要**用、已知的失败模式、工具与判例的时代局限、易混淆的邻近方法论——防止滥用 |

卡片末尾附「相关 skills」（`depends-on` / `contrasts-with` / `composes-with` 三类关系的自然语言说明）与「审计信息」（准入验证判定记录）。

### 4.2 一条流水线，不是八个并列目录

```
                    ┌──────────────────────────────────────────────┐
                    │  08 请求层逆向与签名（参数算不出来时进）        │
                    │  01 锚点 → 02 静态 → 03 数据流 → 04 求解      │
                    │  → 05 脱壳 → 06 工具 → 07 前端面              │
                    └───────────────▲──────────────────────────────┘
                                    │ 参数加密
01 准入 ──→ 02 取数 ──→ 03 反爬 ────┼──→ 04 JS 混淆 ──┐
  │           │            │                        │
  │           │            └──→ 07-03 资产面 ───────┤
  │           └──→ 02-04 会话与身份                  │
  │                                                ▼
  └──────────────────────────→ 05 解析 ──→ 06 工程化
                                            │            │
                                       07-02 采集面      06-04 管道归档
                                          扩量            │
                                                          ▼
                                                    对账报告
```

正常路径是 01 → 02 → 05 → 06；03 / 04 / 08 是**阻力分支**（被拦、代码不可读、参数加密时才进入），07 是**放大器**（量不够时才进入）。六段主流程的进入条件、动作、产出与失败回退见 `流程总纲.md`：

| 段 | 进入条件 | 核心动作 | 产出 |
|---|---|---|---|
| S1 准入 | 拿到目标 | 五个只读信号定入口，选最便宜的取数档 | 入口选型表 + 预估请求量 |
| S2 取数 | 入口已定 | 复现一条最小请求，确认能拿到目标内容 | 一条可重复的成功请求 |
| S3 反爬 | 请求被拦 | 判层；按性价比换身份：TLS → header → IP → 内核 | 通过的请求形态 |
| S4 逆向 | 参数加密/签名 | 锚点 → 静态 → 数据流 → 求解 → 复现签名 | 可生成请求的签名器 |
| S5 解析 | 拿到内容 | 选择器 / 字段建模 / 分页对账 | 字段表 + 解析器 |
| S6 工程化 | 解析器可用 | 队列、去重、断点、增量、限速、归档 | 可复跑的采集管道 |

### 4.3 判层决策树（遇阻先走一遍）

```
请求发得出去吗？
├─ 发不出去 / 抓不到包 ─────────────→ 03-01 通道与封禁（证书锁定/QUIC/双向认证）
└─ 发得出去
   ├─ 401/403/429/空白页 ──────────→ 03-01 换身份四件套（TLS→header→IP→内核）
   ├─ 200 但内容是壳 / 无数据 ─────→ 判 SPA：看 sha256 是否与首页一致
   │     ├─ 一致 → 内容层拦截，转接口层 → S4 逆向
   │     └─ 不一致 → 数据真在 HTML 里 → S5 解析
   ├─ 数据有但缺参数校验 ──────────→ 02-02 接口与表格 / 08-07 前端面
   └─ 数据有但只有几页 ────────────→ 03-05 深度与反爬 / 07-02 采集面扩展
```

## 五、质量保障体系

这套技能库的每个技能都经过两道质量闸门，证据随仓库携带：

### 5.1 准入验证（内容质量）

每个技能入选前通过三重验证，判定记录保留在卡片「审计信息」段：

- **V1 跨域验证**：该方法论在至少 2 个独立语境下成立（不同章节、不同对象、不同结论），排除一时兴起的表达；
- **V2 预测力验证**：用它能推导出一个原始材料未直接讨论的新场景结论，排除「只能复述例子」的描述性内容；
- **V3 独特性验证**：抹掉出处后仍非「任何聪明人都会说的常识」，只保留真正差异化、反直觉的方法论资产。

### 5.2 触发盲测（调用质量）

522 条测试用例（每技能 6–12 条），分三类：`should_trigger`（应激活本技能，257 条）、`should_not_trigger`（不应激活，169 条，其中大量是「应触发近缘兄弟技能」的抢调诱饵，专门防技能间互相抢调用）、`edge_case`（边界场景，92 条，另含 4 条语义模糊用例）。由未参与建设的独立 Agent 做全目录「选择题」盲测——面对一条用户话语，从技能集合中判断该激活哪个技能或都不激活：

- **判卷标准**：`should_trigger` 要求本技能被选中；`should_not_trigger` 要求本技能未被选中；`edge_case` 按预期行为中的「应/不应激活」判定；
- **回炉机制**：每技能设 80% 通过门槛，未达标技能回炉修正触发描述（description / A2 段）后定向复测，失败案例逐条保留；
- 每技能目录下的 `test-prompts.json`（darwin 兼容格式）与 `test-results.md` 完整保留测试基准与结果。

## 六、使用方式

### 6.1 人工使用（按工作流浏览）

```
1. 打开 说明.md → 按大类索引或"你现在的处境"反查表定位子类
2. 打开 流程总纲.md → 确认当前处于六段主流程的哪一段、遇阻走哪条分支
3. 进入子类目录读 说明.md → 按技能清单与触发信号定位技能
4. 打开技能的 SKILL.md → 按 E 段步骤执行，B 段确认边界
5. 按卡片末尾"相关 skills"跳转依赖 / 对比 / 组合技能
```

### 6.2 Agent 装载（自动触发）

将技能目录复制到宿主技能目录（如 `~/.claude/skills/`、`~/.trae-cn/skills/` 或项目级 `.claude/skills/`）。注意：**宿主目录名必须等于 SKILL.md 的 `name` 字段**，改名会让技能失效：

```bash
git clone https://github.com/foxxx1027/Crawler-skill.git
cd Crawler-skill

# 装载全部技能（自动适配两种目录布局，目录名取自 name 字段）
find . -type f -name SKILL.md | while read -r f; do
  src=$(dirname "$f")
  name=$(sed -n 's/^name:[[:space:]]*//p' "$f" | head -1)
  cp -r "$src" ~/.claude/skills/"$name"
done
```

装载后，当对话中出现匹配场景（如「requests 一直 403、浏览器能打开」「这个 sign 参数在哪生成的」），对应技能按其 `description` 自动激活，Agent 按 E 段步骤给出带完成标准的操作指导。

### 6.3 附带工具脚本

`07-扩量与工具链/03-资产面扩张/tools/` 提供两个可直接运行的采集脚本（附 `requirements.txt` 与用法说明）：

| 脚本 | 作用 |
|---|---|
| `harvest.py` | 主采集器：SQLite 队列断点续爬、sitemap 递归、链接/表单发现、JS 端点回灌、代理池与 UA/TLS 指纹轮换、403/429/503 自适应退避、原文与正文落盘 |
| `jsmine.py` | 前端产物挖掘：端点、fetch 调用、GraphQL、云密钥、内网地址、sourcemap、注释里的遗留调试口 |

## 八、约定与说明

- **分类是导航不是边界**：技能的适用范围以其 SKILL.md 的 A2 / B 段为准；07 大类的选型与扩面方法论文档同样可直接使用；
- **顺序纪律**：先判层再花钱——没见过 403 就买代理池、对着 SPA 壳写选择器、没确认接口有数据就还原签名，是三个最常见的顺序错误。正确顺序永远是「入口 → 一条请求 → 判层 → 再决定投入在哪」；
- **每段有验收口径**：如「同一条命令连跑三次都成功」（S2）、「签名逐字节一致、十组样本回归通过」（S4）、「kill -9 后能原地续跑、增量重跑请求数 < 全量 10%」（S6），完整标准见 `流程总纲.md`；
- **合规红线**：本技能库面向公开数据与已获授权的目标。尽调类技能的否决结论输出的是「换数据源或取得授权」，不提供任何规避访问控制的手段。
